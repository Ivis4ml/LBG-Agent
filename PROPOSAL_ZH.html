LBG-Trader.

一个在交易中实现 超越梯度的学习（Learning Beyond Gradients）的框架：从密封式科学评测到有纪律的部署。
Repo  lbg-trader
Paper Sealed-HS
作者 Xin Zhou
      Zheming Liang
状态 草稿

本文同时规范了一个研究产物及其后续可成长为的产品。核心论断可被检验：一个由编码型智能体驱动的框架，能通过代码编辑维护一个持久的交易启发式系统，使其同时达到 科学上可信（密封评测、不变量套件、脱敏反馈）和 工程上可部署（产物冻结、周期性重新发现、实盘执行）。四阶段生命周期正是连接这两项要求的设计。

正文分为四部分。第一部分记录设计如何走到今天的形态，包括若干次具有决定意义的重新构造。第二部分给出方法规范，说明系统是什么、如何学习、如何评测。第三部分规范生命周期，即从发现到实盘部署的四个阶段，以及使两者得以并存的工程切分。第四部分是计划：工程里程碑、风险、已锁定的决策。

I. 本文设计背后的推理
§ 1

本提案如何走到今天

项目最初源自一个问题：Jiayi Weng 提出的 Learning Beyond Gradients[code]（LBG）思想（以编码型智能体维护一个启发式软件系统作为学习对象）能否移植到交易领域？交易看似是合适的应用方向：反馈可被执行、回放免费、基于规则的策略是工业默认；但同时它也比我们考虑过的任何其他领域都更剧烈地考验 LBG 最脆弱的几个假设（分布漂移、信噪比低、回测面对抗性强）。

设计在定稿前经历了若干轮重新构造。其中五轮足够重要，需要明确记录。

重构一：这是 LBG，还是 LLM 引导的贝叶斯优化？

早期版本中，智能体只能编辑一个枚举有限的 YAML 策略文件。一个直接的问题（智能体究竟在编辑代码，还是只是在调 YAML 参数？）暴露了这一版本并非真正的 LBG。它是一种带有持久记忆的 LLM 引导贝叶斯优化（BO），披着 LBG 的术语外衣。按照 Weng 的定义，真正的 LBG 要求智能体编写 代码：新的技术指标函数、新的状态识别器、新的子策略。

修正不是把仅有 YAML 的版本作为 "LBG 第一阶段"，而是认识到 "仅 YAML" 和 "程序合成" 是两个共享基础设施的不同项目。仅 YAML 的配置被重新定位为程序合成系统内部的一个 消融实验。如果完整的 LBG-Trader 不能击败它自己的 DSL-only 消融基线，那么程序合成层就毫无贡献，LBG 论断按其自身标准失败。

重构二：这是一个智能体，还是一个框架？

把四个角色称作"智能体"是一种重要的措辞错误。编辑器、反思器、策展器、翻译器 并非自主、面向目标的循环。每一个都是一次结构化的 LLM 调用，输入和输出均带类型。整个系统是一个 确定性的编排框架，负责调度这些调用，并在调用之间维护持久的启发式系统。这一区分将本项目与 TradingAgents 类工作（每根 K 线都调用 LLM 决定交易）拉开距离，并将其归入 LangProp 类工作（LLM 作为代码空间的优化器）。

"LBG-Trader 不是一个智能体。它是一个利用四类 LLM 角色维护启发式系统的框架。"

重构三：这是研究产物，还是产品？

原始文档将项目定位为一个密封式研究产物，交付物是一份评测裁定报告。一个直接的请求（我希望它至少在仿真层面被实际使用）暴露了这种定位的不完整。诚实的回答是：密封评测与持续部署在同一模式下存在内在张力，二者不可兼得。解决方案是一个四阶段生命周期：密封评测的发现阶段、前向验证阶段、模拟交易阶段、实盘资金阶段。策略在两次重新发现 之间 是冻结的，仅在重新发现 时刻 被刷新。每一次重新发现消耗一段全新的密封窗口数据。这正是量化行业实际采用的做法，既保留每一次裁定的科学可信度，又支持持续运行。

仍然存在的诱惑（让智能体在线运行、持续学习、永不冻结）在 §15 中得到了诚实讨论。简言之：那是另一个研究问题，而不是本项目的延伸。

重构四：从故事到规范

本文上一版本把故事讲清楚了，但停在了"无法实现"这一边。一次仔细的审阅指出了四处规范空白：启发式系统被命名但未被形式化；编排器被默认存在但未被规范；记忆被描述为若干文件，却没有作为带类型的状态系统加技能档产物来定义；评测仍然是一份指标清单，而不是一个预注册的统计检验。本版本在 §4.5、§6.5、§6.6 和 §10.5 中弥补了这些空白。叙述章节保持不动；规范章节是新增的。只关心论证的读者可在第二部分 §6 之后停下；希望真正构建系统的读者可从 §4.5 开始读到 §10.5。

重构五：单次门控与最终裁定

对规范版本的一次审阅暴露了一个更隐蔽的问题：验证门控的统计严格度在两种截然不同的用途之间被混为一谈。在仅有约 500 个交易日的验证窗口上，对 每一次 试验都要求 95% 置信区间下界严格大于 0 的配对自助检验，将使发现循环陷入饥饿，并把接受偏向那些改变换手率的编辑；这些编辑比微妙的 alpha 改进更容易产生统计显著差异。§9 中的修正是：单次门控使用一个更宽松的多目标效用下界加帕累托改进准则；最终 H1 裁定则把严格的配对自助检验保留给一次性的密封评测。§10.5 的统计装置保持不变；被放宽的是单次试验诊断。本版本还以 前缀稳定性 作为无前瞻不变量的正式名称，引入了"因子卡片"（alpha card）这一从策略产物中切出已接受信号的薄产物，并明确承认：禁止数据窥探的机制只能防范文本层面的泄漏，无法防范底层 LLM 在预训练中对特定历史时期形成的先验。

这五次重构确定后，本提案对第一阶段里程碑冻结为规范。进一步的讨论应归入实现仓库的 IMPLEMENTATION.md 与预注册的 analysis_plan.yaml，不再写入本文。

§ 2

用一段话说清楚这是什么

LBG-Trader 是一个框架，它调度四类结构化的 LLM 角色（编辑器、反思器、策展器、翻译器）在交易场景下完成 Weng 所说的 HL：通过直接编辑代码来维护一个启发式系统。本项目中的启发式系统是 indicators/*.py（智能体编写的 Python 因子函数）、strategy.yaml（组合它们的 DSL 配置）、固定引擎 policy_interpreter.py，以及若干显式记忆层的并集。在这一系统内，一次发现运行的核心产出，是智能体编写且通过密封测试的 Python 因子函数集合。每个这样的函数 就是 一个因子的可执行形态，与既有文献在 knowledge/factors/dossiers/ 中以声明式描述的对象，是同一对象的两种翻译形态（声明式 dossier ↔ 可执行 Python）。框架维持这一双向往返：以 dossier 为输入假设，以 Python 代码为输出，并附带密封测试证据。同时也产出一个组合后的冻结策略（第二至四阶段消费它），并为每个函数导出一份因子卡片元数据视图（便于计数、跨运行重组、并反向翻译回 dossier 形式）；但二者都不是被学习的对象。代码才是。

§ 2.5

术语速查表

本文融合了三个领域的词汇：交易、机器学习、软件系统。同时精通三者的读者很少。本节是一份紧凑的术语表，便于读者在阅读后续章节时不必频繁跳转查证。术语按主题分组；想按字母顺序查阅的读者可扫描斜体词条。

交易类术语

术语含义
OHLCV开盘价、最高价、最低价、收盘价、成交量。一根 K 线由这五个数字概括（我们用日线）。15 年 SPY 数据就是一张约 3,780 行的表。
复权收盘价（AdjC）对分红与拆股做事后调整后的收盘价。使用 AdjC 可让"1 拆 2"看起来像平滑减半，而不是突然不连续，从而保证总收益计算正确。
SPY跟踪标普 500 指数的最大 ETF。选 SPY 是因为它流动性好（普通订单不会冲击价格）、覆盖宽（无单一公司风险）、研究充分（任何超额收益都来之不易）。
仓位（position）当前持有的资产数量，按资金比例表示。\(p_t = 1\) 为满仓，\(p_t = 0\) 为空仓，\(p_t = 0.5\) 为半仓。本里程碑禁止 \(p_t > 1\)（无杠杆）和 \(p_t < 0\)（无做空）。
信号 / 指标（signal / indicator）由历史价格计算得到、策略据以决定仓位的数值。例：20 日均线是一个指标；"价格 > 20 日均线则买入"的规则把它变成信号。
夏普比率（Sharpe ratio）年化平均收益除以年化收益波动率：\(\sqrt{252}\cdot\bar r / \sigma(r)\)。把"赚没赚钱"翻译为"考虑波动后赚没赚钱"。夏普 1.0 算好；2.0 罕见；0 与抛硬币相当。
回撤（drawdown）净值曲线相对历史最高点的下降幅度。最大回撤 是测试期内最差的一次。50% 最大回撤的策略，即便长期夏普不错，真人也很难承受。
换手率（turnover）仓位日均变动：\(\overline{|p_t - p_{t-1}|}\)。换手率高意味着频繁交易；低意味着季度调仓。换手率乘以成本即交易摩擦的拖累。
基点（basis point, bp）百分之一的百分之一（即万分之一）。100 美元交易上 5 bp 的成本为 0.005 美元。锁定的单边成本 5.5 bp 意味着一次完整往返成本 11 bp，单笔小，累积大。
成交 / 成交模型（fill / fill model）关于订单何时、以什么价格实际成交的假设。我们采用"信号在第 \(t\) 根 K 线收盘产生，第 \(t+1\) 根 K 线开盘成交"，这是日线的标准纪律，可防止用收盘价信息在同一收盘成交。
滑点（slippage）你想要的价格与实际成交价之间的差距。本项目以 0.5 bp 计入有效成本。
Alpha（阿尔法）无法用"持有市场"解释的超额收益部分。"阿尔法信号"即任何被相信能在扣除成本后产生超额收益的信号。
Beta（贝塔）对大盘的敏感度。SPY 自身按定义 beta 为 1.0。"半数时间做多 SPY"的纯多策略 beta 约 0.5。
制度（regime）市场统计特征大致稳定的一段时期：牛市、熊市、高波动、低波动等。"制度切换"（2020 年新冠崩盘、2022 年加息熊市）是不连续点，常使在前一制度上调好的策略失效。
回测（backtest）把策略作用于历史数据，看它当时会怎么做。本项目整个体系的存在原因，就是因为朴素回测会系统性地说谎。
净值曲线（equity curve）组合价值随时间的累积值：\(\text{Equity}_t = \prod_{s\le t}(1+r_s)\)，从 1.0 起步。策略的视觉外形。
前瞻（lookahead）不小心使用未来信息作出过去的决策。这个 bug 在回测里把平庸策略变得貌似神奇、在实盘里把它们变得灾难性。

LLM 智能体类术语

术语含义
LBGLearning Beyond Gradients。智能体通过 编辑源代码 而非梯度下降更新权重来进行学习的范式。被维护的代码是"学习对象"。
启发式系统（heuristic system）智能体所维护的代码、配置与笔记的集合。本项目中即 strategy.yaml、indicators/*.py 以及记忆文件。在试验 \(k\) 时记作 \(H_k\)。
试验（trial）发现循环的一次迭代：编辑器提议 → 不变量检查 → 回测 → 门控判定 → 反思器解释 → 记忆更新 → 通过则 git 提交。每次发现运行预算 50 次试验。
编辑器 / 反思器 / 策展器 / 翻译器（Editor / Reflector / Curator / Translator）四类 LLM 角色。编辑器每次试验提议一次编辑；反思器解释结果发生的原因；策展器周期性压缩记忆并抽取可复用技能；翻译器在每一次 add_indicator 被接受后把 Python 源码翻译为声明式 dossier。每一个都是一次结构化调用，不是自主循环。
编排器（Orchestrator）按顺序调用四类 LLM 角色、运行不变量与回测、应用门控、写入记忆、提交 git 的确定性 Python 控制平面。其自身不含任何 LLM 调用。
结构化输出（structured output）要求 LLM 返回带类型的对象（本项目用符合 schema 的 YAML），而非自由文本。若输出解析失败，该次试验直接拒绝，不会触发回测。
DSL领域专用语言。本项目指 strategy.yaml 中策略解释器能识别的小型 YAML 语法（过滤条件、仓位算法、出场规则）。编辑 DSL 是两个动作空间之一，另一个是编写新的 Python 指标。
密封评测（sealed evaluation）一种协议：把一段数据（本项目为 2021–2024）从智能体和任何中间决策中锁开，仅在运行末尾揭开一次作为最终裁定。借自临床试验方法学。
不变量（invariant）候选编辑在被允许回测之前必须满足的性质。我们使用静态不变量（对代码做 AST 分析）和动态不变量（扰动数据并验证时刻 \(t\) 的输出不变）。失败则该次试验被拒。
前缀稳定性（prefix-stability）"无前瞻"的正式名称：指标在时刻 \(t\) 的取值必须等于只用至 \(t\) 为止的数据计算所得。比扫描 shift(-1) 更强，能捕获全序列归一化、含未来信息的分位数等微妙泄漏。
脱敏反馈（redacted feedback）告诉 LLM "已接受 / 因回撤恶化拒绝" 等类别，但绝不展示原始验证数值。防止智能体通过无梯度试错过拟合验证集。
奖励黑客（reward hacking）智能体找到设计者未预期的方式让分数升高（如使用未来数据、规避成本、隐藏亏损交易）。不变量套件的存在就是为了让此类行为可被系统性检出。
消融（ablation）移除某一组件（无记忆、无策展器、无程序合成）后运行系统，以隔离该组件的贡献。任何关于"系统为何有效"的诚实论断都需要消融实验支撑。
技能档（skill / skill artifact）策展器从一组被接受的试验中抽取的带类型 YAML 对象：触发条件 + 编辑配方 + 证据 + 已知失败模式。不是自由形式的摘要。
双时间尺度（two-timescale）外层循环（LLM 编辑代码）每次发现运行约 50 次；内层循环（策略决定仓位）每次回测约 3,700 次。两者相差五个数量级。我们绝不把它们合并。

统计与系统类术语

术语含义
分块自助法（block bootstrap）针对存在序列相关性的数据的重抽样方法。不重抽单日（那会假设独立），而是重抽连续 10 天的块，做 1,000 次以计算置信区间。块长选 10 是因为日收益在 1–2 周尺度上存在明显序列相关。
置信区间（confidence interval, CI）以给定概率包含真值的区间。"\(\Delta\)夏普的 95% CI 为 [0.05, 0.40]"意味着产生该区间的程序在重复实验中有 95% 的时间能覆盖真值。
帕累托改进（Pareto improvement）在所有目标上不变差、且至少在一个目标上严格更好的改变。候选者在 Sharpe 不变的前提下使回撤更小，即在 (Sharpe, drawdown) 上帕累托改进。即便效用未上升，本项目的门控也会接受这类候选。
预注册（pre-registration）在 看到 结果之前承诺会运行哪些检验、用哪段数据。防御实证 ML 中最常见的隐性不诚实：看到数据之后再决定测量什么。
族系误差率（family-wise error rate, FWER）同时运行多个检验时，任一 检验为假阳性的概率。本项目用 Holm-Bonferroni 将次级比较的 FWER 控制在 0.05。
AST（抽象语法树）Python ast 模块产生的源代码结构化表示。静态不变量遍历 AST 以检测禁用模式（.shift(-1)、文件 I/O、白名单外 import）而无需实际执行代码。
沙箱（sandbox）受限的 Python 执行环境。候选指标代码在白名单命名空间、CPU 时限内运行，且无文件系统与网络访问。
JSONLJSON Lines，每行一个 JSON 对象，仅追加。事件日志选用它，因易于流式读取且崩溃安全。
Parquet表格数据的列式二进制文件格式。读取比 CSV 快、无损、可按内容哈希版本化。SPY 历史存于单一 parquet 文件。

本文余下出现的术语，若不在上述表内，要么属于标准编程概念（git 提交、schema、命名空间），要么是我们自创且会在首次出现时定义。读者可随时回查本节。

§ 3

本项目在已有工作中的位置

三条研究脉络在此交汇。它们通常彼此互不对话；本项目至少要做的一件事，就是迫使它们之间发生对话。

LBG 脉络（LangProp、Weng、PolicyEvolve、PIBR）

Weng 在 2026 年的博文是直接动机，但更深的先例是 LangProp[code]（Ishida 等，ICLR 2024 工作坊）。LangProp 已经把"LLM 作为代码优化器，依赖可执行反馈"的范式形式化为 PyTorch-Lightning 风格的框架，并在 CARLA 自动驾驶环境中加以应用。Weng 相对于 LangProp 的额外贡献，在于明确把被维护的软件系统命名为 学习对象（启发式系统），并通过实验证明该范式在 Atari 套件规模、配合强编码型智能体的条件下可以工作。PolicyEvolve（2025）与 PIBR（2025）则把同一思想扩展到多人博弈论领域。

这一脉络缺失的是：尚无人将 LBG 带入回测本身具有对抗性的领域：反馈噪声大、历史样本有限、分布漂移是常态、智能体若有机会就会奖励黑客评测框架。交易正是这样的领域。

LLM 交易脉络（TradingAgents、FinMem、FinAgent、QuantAgent）

这一脉络已经拥挤，但与 LBG 互不重叠。TradingAgents[code]、FinMem[code]、FinAgent、QuantAgent[code]（Y-Research-SBU 2025）、HKUDS Vibe-Trading 等工作都把 LLM 智能体 作为交易员：在每一根决策 K 线上调用 LLM 产生买卖动作。该脉络中的"记忆"指的是过往市场状态的记忆，而非过往代码编辑实验的记忆。最接近的概念近亲是早期的 QuantAgent（Wang 等，2024），它使用 writer/judge 内外双循环来精炼 alpha 挖掘脚本。

我们与这一脉络的差别是结构性的、而非渐进性的：我们在回测和执行期间从不调用 LLM。LLM 只在缓慢的外层循环中运行，在两次试验之间编辑代码。这正是 §5 所称的双时间尺度切分。

Hermes 脉络（持续学习、持久记忆）

Hermes Agent 的三层认知架构（run_conversation 处理单次任务，maybe_extract 将有用的模式提交到技能档，curator_cycle 周期性打分、合并、裁剪）是构造持久学习的工作蓝图。我们直接借用这一架构，将三层重命名为编辑器、反思器、策展器，并新增第四类角色翻译器以承担 Python 源码 ↔ 声明式 dossier 的双向往返，整体面向交易场景特化。

II. 方法论
§ 4

论点与假设

论点：一个由编码型智能体驱动的框架，能维护一个持久的启发式系统，其核心产出是一份持续增长的 Python 因子函数库，即智能体亲手写入 indicators/ 下、且在密封测试中幸存的真实文件。每个函数同时以两种可互译的形态存在：可执行的 Python 代码（产物本身），以及与外部因子文献同结构的声明式 dossier（它的可读视图）。在"声明式因子知识"（输入）与"可执行代码"（智能体的输出）之间的双向转化，正是把 HL 范式落入交易场景、而非沦为普通策略搜索的核心机制。被学习的对象是代码；dossier 是它的可读翻译；因子卡片是把两者绑定的元数据视图。

本提案承诺三个假设，并将其视作等价。我们并不私下偏好 H1 胜出。任意一种结局都可成稿。

H1 · 肯定结论
LBG 产出在密封测试中幸存的 Python 因子代码

在等同发现预算下，本框架产出的 幸存 Python 因子函数 数量严格多于随机搜索、贝叶斯优化、单次 LLM 提案与仅 DSL 的 LLM 搜索。幸存因子函数定义为：智能体写入 indicators/*.py 的一个前缀稳定函数，其个体在密封测试上的增量贡献 95% 置信区间下界 > 0。论断的单位是代码本身；每个幸存函数所附的因子卡片是它的元数据索引，而非交付物。

H2 · 方法论结论
密封协议是必需的基础设施

如果缺乏密封划分、脱敏验证与不变量套件，"已验证因子"的表观产量将被过拟合、验证泄漏或奖励黑客所夸大。各项消融（原始验证、无不变量、无记忆、无策展器）使这一夸大幅度可被量化。

H3 · 诚实零假设
LBG 可能未必产出任何幸存因子

即便所有控制都已就位，编码型智能体的学习仍可能无法产出任何在密封测试上个体增量统计显著的因子。交易的噪声与分布漂移也许已经超出 LBG 的表达能力。这一结论本身可独立成稿。

H1 论断的统计单位是 已验证因子，而非组合后的策略。策略仍然交付（它是执行引擎在第二至四阶段消费的组合产物），但 H1 裁定在因子层级做统计。论断所立足的"因子 ↔ Python"双向转化由 §9 的不变量强制：声称是因子、却无法表达为前缀稳定纯函数的对象，不会进入计数。协议被设计为：若 H1 失败，我们仍然知道为何失败；若 H1 成立，因子计数本身就是框架产出的是持久产物、而非一次性幸运策略的证据。

§ 4.5

形式化定义

在规范框架内部细节之前，先固定它所操作的对象。本节有意简短；其价值在于对"被学习的对象是什么、被测量的对象是什么"做毫无歧义的陈述。

市场过程

市场数据是日频 K 线的序列：

\[ D = \{x_t\}_{t=1}^{T}, \qquad x_t = (O_t, H_t, L_t, C_t, \text{AdjC}_t, V_t, \text{div}_t, \text{splits}_t) \] 本里程碑中，标的池为单一标的（SPY），频率为日频，\(T \approx 3{,}780\) 根 K 线，覆盖 2010–2024 年。数据被划分为 \(D_\text{train}\)、\(D_\text{val}\)、\(D_\text{test}\)，在所有智能体可见的上下文中以别名 split_A/B/C 出现。

启发式系统作为学习对象

这是将 LBG 与超参数优化区分开的形式化定义。被优化的对象不是一个参数向量，而是一个持久的、多组件的 启发式系统，按试验编号索引：

\[ H_k = (A_k,\ C_k,\ P,\ I,\ M_k,\ S_k,\ E,\ G_k) \] \(A_k\) · 指标程序集合（indicators/*.py）
\(C_k\) · 策略 DSL 配置（strategy.yaml）
\(P\) · 确定性策略解释器（policy_interpreter.py，跨试验保持固定）
\(I\) · 不变量套件（invariants/*.py，跨试验保持固定）
\(M_k\) · 记忆存储（memory/*.jsonl、accepted_rules.md、failed_directions.md）
\(S_k\) · 技能档存储（skills/*.yaml）
\(E\) · 评测协议（划分、门控、指标；固定）
\(G_k\) · git 谱系（提交、分支、标签）

对照很鲜明。超参数优化运行的是：

\[ \theta_k \;\longrightarrow\; \text{score}_k \;\longrightarrow\; \theta_{k+1} \]

LBG-Trader 运行的是：

\[ H_k \;\longrightarrow\; \text{proposal}_k \;\longrightarrow\; H'_k \;\longrightarrow\; \text{feedback}_k \;\longrightarrow\; H_{k+1} \]

提案是一次代码或配置编辑；候选系统是应用该编辑后的系统；反馈来自不变量与验证门控产生的分类信号。被更新的状态是一个软件产物，而不是一个数值。

策略与仓位

策略是一个由历史观测映射到目标仓位的纯函数：

\[ \pi_H : X_{\le t} \;\longrightarrow\; p_{t+1}, \qquad p_{t+1} \in [0, 1] \] 本里程碑限定为仅做多、无杠杆。第 \(t\) 根 K 线收盘时计算出的信号决定从第 \(t+1\) 根 K 线开盘开始持有的仓位，这从结构上排除了"收盘对收盘"的前瞻泄漏。

前缀稳定性：指标编写契约

任何由智能体编写的指标必须满足的最重要性质是 前缀稳定性。直观地说：在时刻 \(t\) 的指标取值，只能依赖到 \(t\) 为止可获得的数据，而绝不能依赖此后才观测到的数据。

\[ f\!\left(D_{1:T}\right)\!\bigl[t\bigr] \;=\; f\!\left(D_{1:t}\right)\!\bigl[t\bigr] \qquad \forall\, t \in \{1, \ldots, T\} \] 对智能体编写的任意指标函数 \(f\)，将其应用于完整序列时在索引 \(t\) 处的取值，必须等于将其应用于截止到 \(t\) 的前缀序列时在索引 \(t\) 处的取值。这是"无前瞻"的形式化陈述。它比简单扫描 AST 中的 shift(-1) 模式更严格：还能捕获全序列归一化、含未来泄漏的滚动窗口运算，以及任何其他可能让 \(D_{>t}\) 的信息进入 \(f(D)[t]\) 的路径。

编排器的动态前瞻不变量（§9）将其工程实现：对随机抽样的若干 \(t\)，扰动 \(D_{>t}\) 并重新求值候选指标，断言 \(f(D)[t]\) 不变。任何违反前缀稳定性的指标无法进入回测。

之所以将其列为单独命名的不变量，原因在于经验：研究人员在指标实现中最容易意外引入未来信息的形式，是看似无害的全序列变换。例如用整个时期的均值和标准差做 z-score 归一化、用整段序列的分位数做截断、用 fillna(method='bfill') 反向填充。这些操作在 AST 层面看不出问题，但在数值上会让早期时点已经"知道"晚期数据的统计特性。前缀稳定性正面回应了这一类错误。

收益与成本

策略的日度收益，扣除交易成本：

\[ r_{t+1}(H) \;=\; p_{t+1} \cdot R_{t+1} \;-\; c \cdot \lvert\, p_{t+1} - p_t \,\rvert \] \(R_{t+1}\) 为标的的开盘对开盘收益，使用复权收盘价以处理拆分与分红。
\(c\) 为有效的单边交易成本，锁定为 \(c = 0.00055\)（基础 5 bp 加 0.5 bp 的滑点代理）。
成本项由不变量强制：任何候选回测若存在非零换手率却产生零成本，将被拒绝。

评测指标

被门控与最终报告消费的指标定义无歧义：

\[ \text{Sharpe}(H, D) \;=\; \sqrt{252}\;\cdot\;\frac{\overline{r_t(H)}}{\operatorname{std}\bigl(r_t(H)\bigr)} \] \[ \begin{aligned} \text{Equity}_t &= \prod_{s \le t} (1 + r_s) \\[2pt] \text{Peak}_t &= \max_{s \le t}\, \text{Equity}_s \\[2pt] \text{DD}_t &= \frac{\text{Equity}_t}{\text{Peak}_t} - 1 \\[2pt] \text{MaxDD} &= \min_{t}\, \text{DD}_t \end{aligned} \] \[ \text{Turnover}(H, D) \;=\; \overline{\lvert\, p_t - p_{t-1} \,\rvert} \] \[ \begin{aligned} \text{Complexity}(H) \;=\; & \lambda_1 \cdot \lvert A_k \rvert \;+\; \lambda_2 \cdot \lvert \text{filters} \rvert \;+\; \lambda_3 \cdot \lvert \text{params}_{\text{non-default}} \rvert \\ & +\; \lambda_4 \cdot \operatorname{LOC}(\text{indicators}) \;+\; \lambda_5 \cdot \#\operatorname{branches}(P_C) \end{aligned} \] 复杂度权重 \(\lambda_1 \ldots \lambda_5\) 属于锁定清单的一部分，必须在任何发现运行开始之前冻结。策展器（§6.6）读取这一标量以评估系统膨胀；门控将 \(\Delta\text{Complexity}\) 作为拒绝标准之一。

这就是本提案其余部分所依赖的全部形式化装置。任何进一步的内容（自助置信区间、假设结果评分、选择偏倚控制）都将在 §10.5 中分层引入。

§ 5

两个动作空间、两种时间尺度

本项目最重要的一处构造，也是将其与文献中所有 LLM 交易论文区分得最清晰的一条界线，是：两个完全分离的动作空间运行在两种完全分离的时间尺度上。

图 1。 两个动作空间。框架在试验时间尺度上编辑启发式系统（每次发现运行约 50 次事件）。策略在日频时间尺度上决定仓位（每次回测约 3,700 次事件）。两者的事件率相差五个数量级。TradingAgents 类工作把它们压缩进同一个循环，每根 K 线都调用一次 LLM；我们刻意不这么做，正是这种切分使研究可信度与实盘部署同时成为可能。

这一切分为何关键 双时间尺度设计是 §12 中"发现引擎/执行引擎"二分得以成立的前提。它同时使每根 K 线的实盘交易代价低廉（从不调用 LLM），并使密封评测在语义上成立（LLM 在部署期间看不到实盘数据，因此实盘数据在下一次重新发现之前始终未被触碰）。如果缺乏这一切分，项目要么在 token 上贵到无法承受，要么在科学上自相矛盾。
策略产物与因子产物 本领域常见的一处混淆是把 alpha（预测未来收益的信号）与 strategy（信号、风险、仓位、出场的完整机器）混为一谈。本里程碑出于简化考虑将二者合并在同一 YAML 中，但底层的切分确实存在：\(\alpha_t = f_A(X_{\le t})\) 是 indicators/ 中的指标程序，\(\text{position}_t = g_C(\alpha_t,\, \text{risk}_t)\) 则是策略解释器作用于 DSL 配置的结果。后续里程碑可能把 alpha.yaml、strategy.yaml、risk.yaml 拆为独立产物，以支持因子库式工作流，使每张因子卡片携带自己的证据并可在不同组合间组合使用。本里程碑下，单文件足够，分层概念在此存档。

两个动作空间，具体起来是什么样

本节的抽象区分在看到一次具体试验的形态后会变得直观得多。下面并列两次试验，均出自同一启发式系统起点，且都以"接受"结束。左侧的 DSL 编辑是贝叶斯优化基线也能做出的动作；右侧的程序合成是任何参数搜索都产生不了的，因为它给特征表新增了一列。

动作空间 A · DSL 编辑

编辑类型：parameter_change。编辑器调整 strategy.yaml 中的一个数字，不写任何新代码。

编辑前：strategy.yaml 片段：

filters:
  - name: above_sma
    indicator: sma
    window: 20
    relation: price_gt

编辑器提案（YAML 输出）：

type: parameter_change
target: strategy.yaml
path: filters[0].window
old: 20
new: 50
hypothesis: |
  Shorter SMA flips position
  too often in 2018-style chop.
  A longer window should
  reduce false signals.

产物中改变的：一个整数。计算上改变的：指标的回看长度。特征表的 列集合 完全相同。

动作空间 B · 程序合成

编辑类型：add_indicator。编辑器在 indicators/ 中写入一个新 Python 函数，并在 strategy.yaml 中引用。

新文件：indicators/vol_adj_momentum.py：

def vol_adj_momentum(df, lookback=60,
                     vol_lookback=20):
    """Prefix-stable: uses only past."""
    ret = df['AdjC'].pct_change()
    mom = ret.rolling(lookback).sum()
    vol = ret.rolling(vol_lookback).std()
    return (mom / vol).shift(1)

strategy.yaml 的 diff：

filters:
+ - name: momentum_pos
+   indicator: vol_adj_momentum
+   params: {lookback: 60,
+            vol_lookback: 20}
+   relation: gt
+   threshold: 0.0

改变的是：一列新特征（波动率调整动量）被加入系统，加上一条使用它的规则。任何对 strategy.yaml 的参数搜索都无法产生这个信号。

这对 H1 裁定为何重要 §10 中的 DSL-only 消融对应于：让编辑器仅被允许做左侧那种试验。完整 LBG-Trader 两种都能做。如果程序合成类试验从未产生能通过验证、且能切实提升密封夏普的编辑，右侧那一列就在白吃饭，H1 自身的可证伪检验将失败。两动作空间的框架正是把一个本来含糊的对比变成可被度量的对比。
§ 6

四类 LLM 角色

框架把 LLM 的使用分解为四个结构化角色。每一个都是一次类型化输入、类型化输出的 LLM 调用，而非自主循环。这种分解是按职责进行的：将 提议、评估、压缩、翻译 四件事彼此分开，能够阻断 LLM 在被要求评估自身过往提案时所表现出的奉承偏倚，同时使可执行代码与声明式 dossier 之间的双向转换得到明确的承担者。

图 2。 四类 LLM 角色（编辑器 / 反思器 / 策展器 / 翻译器）。外层循环是确定性 Python，负责调度这四类角色，运行不变量与回测，应用验证门控，并提交被接受的编辑。翻译器在每一次 add_indicator 被接受后触发，把 Python 源码转换为与种子库 schema 同构的 JSON dossier（双向转换 round-trip，详见 §6.7）。启发式系统作为 git 跟踪的持久产物存在于底层；持久因子库在 campaign 之间累积，下次 campaign 启动时自动注入 baseline。每一次试验对应一次提交；每一次策展器周期对应一个分支。

编辑器

编辑器读取当前启发式系统的状态，提出恰好一次编辑，并附上假设。动作空间被结构化为八种离散编辑类型：

编辑类型动作内容风险面
add_indicator编写新的纯函数 Python 指标前瞻、沙箱逃逸
parameter_change修改 YAML 中的某个数值参数低
add_filter使用已有指标新增入场过滤条件低
remove_filter移除某个过滤条件低
change_sizing_mode切换仓位算法隐性杠杆
change_exit_rule修改止损或持仓期限低
simplify移除某个组件，须做退化检查能力损失
revert_to_trial_N回滚到先前的某次提交无

编辑器的输出是结构化的 YAML 提案，从不为自由文本。它必须包含一个显式假设，其中预期信号是枚举值，而不是自由形式的预测。这种离散枚举正是反思器证伪环节得以机械化、而非沦为主观判断的前提。

trial_id: 23
hypothesis: |
  Recent rejected trials suggest fixed_fraction sizing is too
  aggressive during high-vol periods. Switching to volatility_target
  should reduce exposure when vol is elevated.

proposed_edit:

  change:

      mode: volatility_target

反思器

反思器在回测与门控之后运行。关键之处在于："假设是否得到确认？"这一问题 不 由 LLM 回答；它由外层循环机械地比较编辑器枚举的预期信号与实际信号后给出。反思器的职责是 解释 结果，而不是 评判 结果。这是本项目对 LLM 奉承偏倚的主要防线。

策展器

策展器每接受 10 次试验运行一次。初始阶段为 影子 策展器：它只能压缩记忆（合并已接受规则、裁剪被新证据推翻的失败方向、报告复杂度指标），而不能修改 strategy.yaml。一旦系统被证明稳定，可启用 主动 策展器，使其提出策略简化建议，并须经过强制的验证复查。策展器使用可用的最强模型（Opus），原因在于压缩是系统中语义要求最高的操作。

翻译器

翻译器在每一次 add_indicator 编辑被门控接受 之后 运行。它不参与提议、不参与评估，仅承担一次受限的、确定性输入输出的转换任务：读入被接受的 indicators/<fn>.py 源码（包含 docstring、参数默认值、被门控记录的训练统计与验证信号），输出一份与 indicators/seed_templates/_index.yaml 中既有种子条目 schema 同构 的 JSON dossier，写入 alpha_cards/dossiers/<fn>_trial_<NNNN>.txt。这一份 dossier 与因子卡片 alpha_cards/<fn>_trial_<NNNN>.yaml 共同构成因子的声明式视图。

翻译器的存在使可执行 Python 与声明式 dossier 的双向往返（round-trip）成为系统的显式承担者，而不是事后人工填表：种子库以 dossier 为入口、编辑器以 Python 为出口，翻译器把出口产物翻译回入口形态，使下一次 campaign 的种子库被自动扩充（§4 因子库自动注入）。翻译器从不评估假设、从不改动启发式系统、从不写入 strategy.yaml；它的所有产物都标注来源 trial，并被 SkillManager 接管入库。翻译器的失败（解析、schema 不符）不会回滚已被接受的编辑——dossier 缺失只是降低该因子在未来 campaign 中的可被检索性。

§ 6.5

编排器

四类 LLM 角色仅在外部调度器的指令下工作。这个调度器（编排器）是一个确定性的控制平面，使整个框架可复现、可审计、能够抵御奖励黑客攻击。它是系统中 不允许 由 LLM 承担的部分。

编排器是一段确定性的 Python 控制平面。它调度结构化 LLM 调用，强制信息边界，应用候选编辑，运行不变量与回测，决定接受或拒绝，更新记忆，并将产物提交到 git。它不作任何主观判断。

组成模块

编排器被拆分为十三个具有单一职责的模块。这种拆分使每个模块都可被独立测试，并允许在不损害密封评测有效性的前提下替换模块实现。

模块职责
ContextBuilder构造每次 LLM 调用所看到的角色专属上下文；强制脱敏。
RoleRunner以类型化输入调用 LLM（编辑器、反思器、策展器或翻译器），并要求类型化输出。
ProposalParser对编辑器的 YAML 输出做语法解析与 schema 校验；无法解析的提案直接拒绝，不会触发回测。
CandidateBuilder将解析后的编辑应用到一个候选 git 分支；门控接受之前不触碰 main。
SandboxExecutor在受限命名空间中运行候选指标代码，并设置超时与内存限制。
InvariantRunner执行 schema、AST 静态、动态前瞻、数据窥探、成本模型等检查；对失败进行分类。
BacktestRunner运行训练集、验证集回测；运行末次密封回测（仅一次）。
ValidationGate应用多目标门控，包括分块自助统计检验；输出脱敏后的分类信号。
HypothesisScorer机械地比较编辑器枚举的预期信号与实际信号；反思器无权执行该比较。
MemoryManager写入仅追加的事件记忆；应用反思器产生的压缩记忆更新。
SkillManager维护技能档存储；策展器的输出经此模块写入。
GitManager每次试验一次提交，每个策展器周期一个分支；提供完整审计谱系。
SealedVault仅写一次的容器，存放 sealed_test_final.json；拒绝任何二次写入。
ReportBuilder由所有记录产物生成最终 HTML 报告。

发现循环的形式化描述

完整发现流程足够小，可以完整写出。下面是实现必须满足的契约：

算法 1 · 发现循环 
def discovery_loop(H0, D_train, D_val, D_sealed, budget):
    H = H0
    sealed_opened = False

    for k in range(budget.max_trials):
        # 1. 构建角色专属上下文（脱敏在此处强制执行）
        ctx = ContextBuilder.editor_view(H)

        # 2. 编辑器提出单次编辑，并附带显式假设
        proposal = RoleRunner.editor(ctx)

        # 3. 解析与 schema 校验
        if not ProposalParser.valid(proposal):
            MemoryManager.log_reject(k, "invalid_proposal")
            continue

        # 4. 将编辑应用到候选分支
        H_candidate = CandidateBuilder.apply(H, proposal)

        # 5. 在任何回测之前先运行不变量
        inv = InvariantRunner.run(H_candidate)
        if not inv.all_pass():
            outcome = inv.failure_category   # safety / quality / hard
            MemoryManager.log_invariant_failure(k, proposal, inv)
            RoleRunner.reflector(ContextBuilder.reflector_view(
                proposal=proposal, train=None,
                validation_signal=outcome, decision="reject"))
            continue

        # 6. 训练集与私有验证集回测
        train_result = BacktestRunner.run(H_candidate, split="train")
        val_result   = BacktestRunner.run(H_candidate, split="validation")

        # 7. 机械化门控；智能体看不到任何数值
        decision = ValidationGate.decide(H, H_candidate, train_result, val_result)
        signal   = ValidationGate.redact(decision)

        # 8. 机械化假设结果判定
        hyp_outcome = HypothesisScorer.compare(
            expected=proposal.expected_validation_signal,
            actual=signal)

        # 9. 反思器只做解释（不评判），并写入记忆更新
        reflection = RoleRunner.reflector(ContextBuilder.reflector_view(
            proposal=proposal,
            train=train_result.public_summary(),
            validation_signal=signal,
            decision=decision.kind,
            hypothesis_outcome=hyp_outcome))
        MemoryManager.apply(reflection)

        # 10. 提交或丢弃
        if decision.accept:
            H = GitManager.merge_candidate(H_candidate)
            SkillManager.maybe_extract(H, proposal, reflection)

        MemoryManager.log_trial(...)

        # 11. 策展器按调度运行，不会因事件被动触发
        if CuratorScheduler.should_run(H):
            c = RoleRunner.curator(ContextBuilder.curator_view(H))
            MemoryManager.apply_curator(c)
            GitManager.commit_curator_branch(c)

    # 12. 密封测试恰好打开一次，由编排器执行，绝不由 LLM 执行
    assert not sealed_opened
    sealed_result = BacktestRunner.run(H, split="sealed")
    SealedVault.write_once("sealed_test_final.json", sealed_result)
    return ReportBuilder.build(H, sealed_result)

§ 6.6

记忆与技能档

本框架中的"记忆"不是"LLM 记住了什么"。它是一套结构化的持久状态文件系统，按层划分，每一层具有不同的生命周期、审计保证与消费者。混淆这些层正是 Hermes 类系统逐步退化的方式；将它们彼此分开，则使持久化从"碎片记录"上升为"科学积累"。

四层记忆

层次文件属性
事件记忆 memory/trials.jsonl、reflections.jsonl、invariant_failures.jsonl、agent_compute.jsonl 仅追加，永不重写。这是"发生了什么"的真值日志。
语义记忆 memory/accepted_rules.md、failed_directions.md、open_questions.md、do_not_repeat.md 由反思器压缩，面向读者的散文体。供编辑器作为上下文使用。

编辑器读取语义记忆和技能档，而不直接读取事件记忆。原因是机械性的：把 50 次试验的原始 JSONL 喂给每一次编辑器调用，会撑爆上下文窗口，并以本应被反思器过滤掉的噪声污染决策。事件记忆用于审计；语义记忆与技能档用于复用。

技能档：压缩后的可复用编辑配方

一份 技能档 并非摘要。它是策展器从一组被接受试验中抽取出的带类型对象。这一区分必须清晰陈述：

"记忆是'发生了什么'。技能档是'带证据、带已知失败模式的压缩可复用编辑配方'。"
技能档示例（skills/vol_target_after_drawdown_regression.yaml） 
skill_id: vol_target_after_drawdown_regression
status: active

trigger:
  validation_signal: rejected_drawdown_regression
  common_context:
    - fixed_fraction sizing currently active
    - trend-following signal passes train
    - turnover or drawdown elevated

recipe:
  edit_type: change_sizing_mode
  change:
    sizing:
      mode: volatility_target
      target_vol_range: [0.08, 0.15]
      max_position: 1.0

evidence:
  accepted_trials: [12, 18, 27]
  rejected_trials_that_motivated_it: [9, 11]

known_failure_modes:
  - target_vol below 0.08 often undertrades
  - target_vol above 0.15 can fail drawdown gate

complexity_cost: 1.0
last_curated_at_trial: 30

这一 schema 正是使策展器在 LBG 意义上成为 历史压缩算子 而非"摘要撰写者"的关键。技能档必须引用具体证据（试验编号），必须描述触发条件，必须枚举失败模式，并且必须在每一次策展器周期被复审。最近无正向证据的技能档将被废弃；与新证据矛盾的技能档将被合并或裁剪。

§10.5 中定义的"模式复用率"度量了编辑器在提出编辑时引用现有技能档的频率，这是对技能档存储是否真的在起作用的直接实证检验。

§ 6.7

因子库作为原材料

一个能把本提案大部分内容串起来的观察：几乎每一个已发表的量化因子，本质上都是历史 K 线的一个前缀稳定纯函数。Aroon、RSI、ADX、应计盈余、Amihud 流动性、订单流不平衡、波动率调整动量：输入不同，动机不同，但目标形态相同：一个从"价格+量"历史映射到逐 K 线数值的函数。一个无法写成此形态的因子，几乎必然违反无前瞻规则，本不该被发表。

这正是智能体 add_indicator 编辑类型瞄准的形态。编辑器的编写契约（§9）、AST 检查、沙箱、前缀稳定性，全部对准同一目标。这意味着既有的量化因子文献，从 LBG-Trader 的视角看，就是一份候选 Python 函数的 种子库，编辑器可从中汲取。本项目不必从空白页起步。

磁盘上的布局

该资源物理上存放于 knowledge/factors/，刻意与 memory/ 分离。这一切分至关重要：memory/ 是发现循环 在运行过程中 产生并维护的（§6.6）；knowledge/ 是只读材料，存在于任何运行之前，且被所有运行共享。把两者混在一起会模糊"memory 是本次发现产出的东西"这条边界，而 §6.6 的四层记忆分类正依赖此边界成立。

布局采用两层结构：一个用于检索的追加式 JSONL 索引，加上每份因子-版本一份不可变的档案文件以供全文阅读。

解析状态：对"哪些有结构"的诚实记录

这些档案由不同 LLM 运行在不同时间撰写，约 40% 含有严格 JSON 无法解析的内容（通常是裸 LaTeX \frac{} 未转义，或 schema 在批次间漂移）。与其假装 564 份都是干净 JSON，索引明确记录已知状态：

parse_status数量含义
strict336直接经 json.loads 加载，检索层可使用结构化字段。
fixed2对非法反斜杠转义后才加载成功，结构可用但略经归一化。
raw226无法解析。档案以原始文本保留；索引中的 one_line 是正则抽取的片段。

338 份可解析档案中，271 份抽得明确 category；其余使用非标准 schema，无可识别的类别键。编辑器与检索助手被告知哪些档案有结构、哪些只有原始文本，从不把后者当作有可靠结构的内容处理。

追加式设计

索引文件是 仅追加 的，刻意效仿 memory/trials.jsonl（§6.6）的纪律。新增一份档案（或为已有因子的研究新增一个版本）只需一个动作：在 index.jsonl 追加一行，并在 dossiers/ 下放入一份新的不可变文件。废弃某因子则在新追加的行上设 status: deprecated 字段，而不是改写旧行。其好处与任何追加式日志一致：天然崩溃安全、grep 友好、保留完整版本历史、并发扩展无合并冲突。

两点值得指出。其一，档案本身不可变：下季度重新研究 Aroon 因子会产出新文件 Aroon_20260815_xxxxxx.txt，而不是覆盖。检索按时间戳选最新版本；旧版本仍是可被引用的历史产物。其二，索引可无限增长；当前 564 行约 420 KB；即便 50,000 行也只有约 35 MB，仍可 grep、仍可在内存中缓存。

编辑器如何使用

检索助手在 lbg/knowledge/factors.py，提供三个刻意保持极小的函数：

# → 按子串匹配排序的元数据列表

# → 全部 564 条元数据；进程内缓存

检索是对 factor_name / category / one_line 三字段的子串匹配。在 564 条规模下用嵌入是过度工程。若语料规模将来上升到几千条，可在不改变外部接口的前提下替换为真正的检索索引；这正是它独立成模块的理由。

ContextBuilder 用当前试验上下文（最近的拒绝、在位策略的过滤条件）派生的关键词调用 search()，取前几条命中，把它们的 one_line 摘要塞进编辑器提示。编辑器若需完整档案，可按 factor_name 引用，get_dossier 按需取出。要点：每次试验编辑器只看到小而相关的切片，从不把 564 份档案当批量上下文。

该库 不 被允许跳过任何不变量或密封评测检查。档案引用只是假设文本中的证据，而不是对前缀稳定性或验证门控的豁免。一个背后有五篇论文的因子，仍可能在 SPY 2021–2024 的密封测试上失败；一旦失败，它就像任何其他候选一样被拒。该库是搜索的输入，不是权威性输出。

那么 LBG-Trader 的真正产出是什么

若框架按设计运行，因子卡片导出流程（§6.6）在多次发现运行积累后，将产出种子库的 已验证子集：一个在所研究标的池上、在锁定协议下确实展示出在密封测试上有增量贡献的因子库。对照如下：

因子的形态 它是什么 它独自缺什么
声明式形态，knowledge/factors/dossiers/Aroon_20260427_023945.txt 一份人/LLM 可读的因子档案：严格定义、金融意义、参数化提示、组合模式、过拟合提醒。静态文本，不可执行。 不可运行；无密封测试证据；无法证明该因子在本标的池、本成本模型下产生增量夏普。
可执行形态，indicators/aroon.py（本次发现运行中智能体亲手编写的文件之一） 一个真实的 Python 纯函数，回测引擎直接调用它。可被执行、可被版本化、可被组合进策略、可被 leave-one-out 消融以支撑 H1 计数。这才是 LBG 真正维护的对象。 独自缺乏面向人的描述；其叙事意义依赖于 docstring 与对应 dossier 翻译。
因子卡片，alpha_cards/trial_NNNN.yaml 把上述两种形态绑定起来的元数据视图。Schema 是 dossier schema 的超集：既携带声明式字段（定义、动机、参数化），又携带可执行证据（.py 的文件路径、前缀稳定性状态、密封 CI）。用于计数（H1）、组合（投资组合里程碑）、反向翻译回 dossier 形式。 不是产物本身，只是索引条目。没有底层的 .py 与 dossier 文本，卡片只是个空壳。

要点：同一因子以三种形态存在：dossier、Python 函数、把二者链接的卡片。发现运行消费 dossier（检索）、产出 Python 函数（H1 的统计单位）、导出卡片（让函数可被计数、可复用、可反向翻译）。启发式系统是三者的并集；Python 函数是其中 LBG 真正产出的那部分。

这一重新构造为何重要

本项目最具雄心的论断（我们也应明示）是：LBG-Trader 最持久的输出 不是任何单一策略产物，而是因子卡片这份缓慢生长的图书馆。一次成功的发现运行产出一个冻结策略，加若干新的已验证因子卡片。策略在下一次重新发现时失效；因子卡片留存、携带证据、可在未来策略间组合，并在其证据失效时被干净地废弃。

在这一构造下，knowledge/factors/ 是 之前 的图景（论断而无验证），多次发现运行之后的因子卡片集是 之后 的图景（论断 + 验证 + 参数化 + 可组合性元数据）。若 H1 成立，框架的经济价值正是这两份图书馆之间的差量。

对 §18 工程计划的实际影响

这一重新构造影响四处工程选择，其中两处已经在代码树中：

  • 检索助手：已交付。lbg/knowledge/factors.py 暴露 search()、get_dossier()、load_index()。当前规模下子串匹配足够；接口稳定到将来可在不改调用方的前提下替换为嵌入检索。

  • 因子卡片 schema 锁定。 因子卡片旨在比其源策略更长寿，其 schema 因而承重。§6.6 中的 schema 现在被视作锁定清单（§20）的一部分，而非实现细节。
  • 跨策略因子复用。 后续里程碑可把现有因子卡片作为新一次发现运行的启发式系统起点。密封性仍然保持（采用新的密封窗口），框架得以把过往优秀发现摊销使用。

§ 7

数据与三划分协议

数据被刻意设计得朴素。SPY 日频 K 线，自 2010-01-04 至 2024-12-31，通过 yfinance 获取，与 Stooq 交叉核验后存为版本化 parquet。包含 OHLCV、复权收盘价、分红与拆分。共十五年，约 3,780 个交易日。

图 3。 三划分协议。训练集长度足以获得统计功效；验证集刻意包含一次市场制度切换，使门控具有锋利度；密封集长度足以覆盖多种制度。智能体并不知道这些是哪几个日历年份；划分对智能体而言只用别名字母指代，以阻止 LLM 利用其预训练中关于具体市场事件的先验。

反窥探机制及其边界

智能体不得看到日历年份或命名的市场事件。划分在提示上下文中始终以别名（split_A、split_B、split_C）出现。一个不变量会扫描智能体输出中的禁用词（年份数字、事件名称）。

这道防线只针对显式的文本泄漏，无法防范模型潜在的预训练先验。 底层 LLM 的训练数据中包含关于 SPY 2020 年回撤、2022 年熊市等内容的评论，这些先验我们无法清除。因此，最终裁定的诚实表述是：它评测的是 在可获得公共先验下 的 LLM 辅助代码空间搜索，而不是白板式学习。这一限制在最终报告中显式记录。

§ 8

回测

回测采用向量化实现，约 150 行 Python。选择向量化既出于速度考虑（每次发现运行需进行数百次回测），也因为动态无前瞻不变量更容易在向量化运算中接入。

  • 成交模型。 第 \(t\) 根 K 线收盘时产生的信号，在第 \(t+1\) 根 K 线开盘成交。禁止"收盘对收盘"的成交。
  • 成本模型。 锁定为 单边有效 5.5 基点，分解为基础 5.0 bp 加 0.5 bp 滑点代理。形式定义见 §4.5；不变量强制成本非零。
  • 滑点代理。 0.5 bp 已计入上述有效成本之中，不另作调整。
  • 仓位算法。 long_only_full、long_only_fraction、volatility_target。本里程碑不做空、不加杠杆。
  • 前瞻防护。 第 \(t\) 根 K 线的信号仅使用至 \(t\) 为止的数据，通过显式的 .shift(1) 向量化实现。动态不变量扰动未来数据，并验证 \(t\) 时点的仓位保持不变。

§ 9

不变量与验证门控

不变量套件是把"LLM 在做程序合成"与"LLM 在奖励黑客回测框架"区分开的关键。如果缺失这一套件，一个不受约束的编码型智能体会在几次试验之内就发现前瞻、规避成本、窥探数据或利用索引对齐的漏洞。

静态不变量：文件与 schema 层

  • config_schema · strategy.yaml 通过 schema 校验
  • no_python_edit · 智能体不得修改 backtest.py、policy_interpreter.py 等基础设施
  • no_forbidden_file_access · 智能体只能读取白名单文件
  • no_data_snooping · 扫描智能体输出中的年份数字与事件名称

静态不变量：AST 层（针对指标编写）

  • no_negative_indexing · 禁止形如 df.iloc[i+k]（k 为正）的写法
  • no_future_shift · 禁止 .shift(-N)
  • no_forward_fill_future · 禁止任何会引入未来数据的填充
  • whitelisted_imports_only · 仅允许 numpy、pandas、math
  • pure_function · 不得有全局状态、副作用、I/O

动态不变量：运行时

  • prefix_stability · §4.5 中给出的形式陈述；工程化方式为：对随机抽样的若干 \(t\) 扰动 \(D_{>t}\)，重新求值候选指标，断言 \(f(D)[t]\) 不变。这是最严格的无前瞻检查，能够覆盖静态 shift 检查，并额外捕获全序列归一化、含未来信息的分位数计算及其他微妙泄漏。
  • position_invariance · 把同样的扰动测试应用于策略 仓位，而非仅指标输出，以防 DSL 组合层引入新的泄漏。
  • cost_model_required · 确认回测在非零换手率下产生与之成比例的非零成本
  • max_position · 确认无隐性杠杆
  • sandbox_execution · 指标函数在受限命名空间中运行，并设有超时

智能体编写的指标函数必须满足下述契约，并在其文档字符串中记录：

指标函数契约 
def my_indicator(df: pd.DataFrame, **params) -> pd.Series:
    """
    Pure, deterministic, prefix-stable.

    No file IO, network, env vars, random state, global mutable state.
    Output index must equal df.index.
    Output[t] must depend only on df.loc[:t].

    Prefix-stability requirement (enforced by dynamic invariant):
        f(df.iloc[:T])[t] == f(df.iloc[:t+1])[t]   for all valid t.
    """

验证门控在不变量通过、训练与验证回测完成之后应用，采用多目标判定。单次试验门控与最终 H1 裁定有意采用不同的检验。 验证集仅含约 500 个交易日；若对每一次试验都要求 95% 置信区间下界严格大于 0 的配对自助检验，将导致发现循环陷入饥饿，并把接受偏向那些显著改变换手率或波动的编辑；这类编辑更容易制造统计显著差异，却不必然对应真实 alpha。最终裁定在密封测试上仅作一次，使用 §10.5 规定的严格自助检验。

单次试验验证门控伪代码 
def accept_or_reject(current, candidate, train, validation):
    if train.num_trades < MIN_TRADES:
        return Reject("too_few_trades")
    if validation.max_drawdown < current.max_drawdown * 1.15:
        return Reject("drawdown_regression")
    if validation.turnover > MAX_TURNOVER:
        return Reject("turnover_too_high")
    if complexity(candidate) - complexity(current) > MAX_DELTA:
        return Reject("complexity_increase")

    # 带不确定性惩罚的多目标效用
    # （并不要求 CI > 0）
    u_cand = utility_lcb(candidate.validation_returns, alpha=0.20)
    u_curr = utility_lcb(current.validation_returns,   alpha=0.20)

    if u_cand > u_curr + EPS:
        return Accept("utility_improvement")

    # 即便无效用增益，帕累托改进者亦予接受
    if pareto_dominates(candidate, current,
                        keys=("validation_sharpe", "max_drawdown",
                              "turnover", "complexity")):
        return Accept("pareto_improvement")

    if train.sharpe - validation.sharpe > MAX_TRAIN_VAL_GAP:
        return Reject("overfit_gap")

    return Reject("no_meaningful_improvement")

有两处设计选择值得点明。第一，单次门控使用 \(\alpha = 0.20\) 的单侧效用下界，相较最终裁定所用的 95% 置信区间更为宽松，从而允许具有信息量的探索，同时仍对高方差候选施加惩罚。第二，帕累托改进的候选（在回撤、换手率或复杂度上有改善，而在夏普上不变差）将被接受：这能阻止循环固守单一在位策略，并奖励纯夏普选择会漏掉的风险结构改进。

智能体仍然只接收类别化结果，不接收任何具体数值，因此外层循环验证与智能体可见反馈之间的密封性，不受此门控结构的影响。

§ 9.5

五种攻击与对应的拦截

抽象的不变量清单难以评估其价值。本节走过一个足够强的编码型智能体可能尝试的五种 具体攻击，每一种对应的不变量或检查，以及编辑器看到的拒绝信号。它们都不是假想；其变体已在多份关于 LLM 编码型智能体滥用评测框架的公开报告中出现。本节意在让读者直观看到：不变量套件不是可有可无的装饰，它正是允许 H1 裁定具有任何含义的全部前提。

攻击 1 · 最常见的：把目标前移用作特征

最简单也最尴尬的攻击：把目标变量向前 shift，再当作特征使用。

indicators/clever_signal.py：坏指标 
def clever_signal(df):
    """A 'predictive' signal."""
    future_return = df['AdjC'].pct_change().shift(-1)
    return (future_return > 0).astype(float)

被拦截的位置： no_future_shift（静态 AST 检查）。字面量 .shift(-1) 是禁用模式，检查在任何回测之前触发。

编辑器看到： rejected_invariant_failure（类别：safety_fail）。反思器摘要记录："ast_static check forbade .shift(-N) in indicator function"。该次试验被记录，但任何指标数值从未产生。

攻击 2 · 微妙变体：全序列归一化

已经内化了静态规则的智能体可能尝试用归一化技巧规避检查。下例能通过 AST 检查，因为没有出现 .shift(-N)。

indicators/zscore_momentum.py：看似无害 
def zscore_momentum(df, lookback=60):
    raw = df['AdjC'].pct_change().rolling(lookback).sum()
    # Normalise across the full series for "stability"
    return (raw - raw.mean()) / raw.std()

该 bug 在 AST 层不可见：raw.mean() 与 raw.std() 是对 整段 序列计算的，因此时刻 \(t\) 的取值悄悄依赖于 \(t\) 之后的数据。在回测中，此信号会显得校准得离奇地好。

被拦截的位置： prefix_stability（动态检查）。运行器分别在完整训练序列与截至 \(t\) 的前缀序列上计算指标，对若干抽样的 \(t\) 进行比对。结果在数值上存在微小但非零的差异，断言失败。

编辑器看到： rejected_invariant_failure；反思器摘要："prefix_stability check found indicator value at t=1000 differs between full-series and prefix evaluation by 0.043; whole-series statistics are not allowed"。编辑器从记忆中习得："不要使用未居中或未按窗口缩放的全序列统计"。

攻击 3 · 用异常处理隐藏亏损

面临指标压力的智能体可能尝试在 try/except 块内吞掉亏损交易，期望门控只统计幸存下来的交易。

对仓位逻辑的提议改动：坏 
def position(signal, ret):
    try:
        # Only count this bar if return is positive
        assert ret > 0
        return signal
    except AssertionError:
        return 0

被拦截的位置： no_python_edit（智能体根本不允许编辑 policy_interpreter.py，仓位逻辑在那里）且 若它把这段写进某个指标内，whitelisted_imports_only 也会失败（指标返回一条序列，而非按 K 线决策，结构本身不合法）。即便某个创造性的变体绕过了两者，cost_model_required 也会拦截：丢弃交易而不记录对应成交与成本的策略，其交易数与成本将不再与换手率成比例。

编辑器看到： rejected_invariant_failure，附被禁模块的具体名称。该次试验以 safety_fail 类别记录，并计入最终报告第三层的 safety_fail 计数。

攻击 4 · 绕开文件系统偷读原始 OHLCV

编辑器的上下文本来应是脱敏的，但一个 Python 指标可能尝试在执行期间直接读取数据文件以绕过脱敏。

indicators/cheater.py：坏

被拦截的位置： whitelisted_imports_only 允许 pandas 模块，但 sandbox_execution 在禁止文件系统访问的命名空间中运行指标；pd.read_parquet 抛出 PermissionError。即便读取意外成功，.shift(-1) 仍会触发 AST 检查。

编辑器看到： rejected_invariant_failure；反思器摘要："sandbox_execution: filesystem access denied"。编辑器的记忆累积起明确的"不要尝试 I/O"规则。

攻击 5 · 用命名探测日历信息

编辑器看不到日历年份，但它可能在假设文本中提出引导性问题，期望反思器（确实能看到一些指标摘要）补全空白。

本节是什么，不是什么 本节并非安全审计。一个足够坚定的对手原则上可以发明当前不变量套件未预见到的攻击（如把未来数据编码进指标的 docstring、利用前缀稳定性检查容忍的浮点小技巧等）。不变量套件的设计目标是赢下常见情形，而不是对无限对手做到密不透风。§10 中的 无约束 Python 消融 就是对"关闭套件后情况会糟糕到什么程度？"的实证回答，也是项目能为 H2 提供的最有力证据。

第零层：在一切之前的健全性检查

在任何 LLM 驱动的试验运行之前，回测引擎必须先通过五项健全性检查。它们是工程计划第 1 周的退出条件：

  • 买入持有指标与独立实现的参考值在容差范围内一致。指示性区间：SPY 2010–2018 年化夏普视成本假设处于 0.7–0.9 区间，本提案不预先承诺确切数值，但承诺与独立实现一致。
  • 随机搜索在扣除成本后的中位夏普接近零。
  • SMA 双均线在两次独立运行中按位等价（bit-equivalence）。
  • 动态前瞻不变量能够捕获一个合成的作弊指标。
  • 成本模型不变量能够捕获一个合成的零成本回测。

任一第零层检查失败，发现运行不得启动。

第一层：基于已验证因子的密封裁定

H1 的分析单位是单张因子卡片。一张卡片被 验证 当且仅当其个体在密封测试上的增量贡献，95% 置信区间下界 > 0。H1 头条检验对各系统的已验证卡片做计数比较。

步骤 1 · 单卡片的增量密封夏普

对每张在发现运行中被接受的因子卡片 \(c\)，定义"包含 \(c\)"与"剔除 \(c\)"的两个策略解释器，并计算各自的日收益序列：

\[ r^{\text{with } c}_t = \pi_{H \setminus \{c\} \cup \{c\}}(X_{\le t})\, R_{t+1} - \ldots, \qquad r^{\text{without } c}_t = \pi_{H \setminus \{c\}}(X_{\le t})\, R_{t+1} - \ldots \] \[ \Delta r^{c}_t \;=\; r^{\text{with } c}_t \;-\; r^{\text{without } c}_t, \qquad \Delta S_c \;=\; \sqrt{252}\;\frac{\overline{\Delta r^{c}_t}}{\operatorname{std}(\Delta r^{c}_t)} \] \(\Delta S_c\) 是卡片 \(c\) 加入到 \(H \setminus \{c\}\) 时所贡献的年化信息率。在 \(D_\text{sealed}\) 上仅在运行末尾评测一次。
操作性定义：pathwise 增量（而非严格 LOO） 本提案在第一阶段把 \(\Delta S_c\) 的操作性定义固定为 pathwise 增量夏普：按照该卡片在发现循环中被接受的时间顺序，将 "已接受卡片 \(\le c-1\) 的策略" 与 "已接受卡片 \(\le c\) 的策略" 在密封窗口上的日收益相减，得到 \(\Delta r^{c}_t\)。这一定义满足两点工程约束：(1) 它与发现过程本身的组合方式一致，每张卡片承担其 边际 贡献，而不是回顾性地被赋予对完整集合的反事实贡献；(2) 它只需要在密封窗口上对 \(|\text{cards}|\) 个累计策略各做一次回测，复杂度 \(\mathcal{O}(N)\) 而不是严格 LOO 所需的 \(\mathcal{O}(N \cdot T)\)。第二阶段及之后，可在补充材料里报告完整 LOO 版本作为稳健性检查；H1 的预注册裁定以本节定义的 pathwise 版本为准。

步骤 2 · 对单卡片贡献做分块自助置信区间

\[ \operatorname{CI}_{95}(\Delta S_c) \;=\; \text{moving block bootstrap}\bigl(\Delta r^{c}_{1:T_\text{sealed}};\ \text{block\_len}=10,\ n=1000\bigr) \] \[ c \text{ 为 } \mathbf{\textit{已验证}} \;\;\iff\;\; \operatorname{lower bound}\bigl(\operatorname{CI}_{95}(\Delta S_c)\bigr) \;>\; 0 \]

步骤 3 · H1 的计数检验（按系统）

\[ N^{\,\text{val}}_\text{LBG} \;=\; \#\bigl\{ c \in \text{cards}_\text{LBG} : c \text{ 被验证} \bigr\} \] \[ N^{\,\text{val}}_{B^{*}} \;=\; \#\bigl\{ c \in \text{cards}_{B^{*}} : c \text{ 被验证} \bigr\} \] 对每个预注册系统（LBG-Trader、DSL 上 BO、网格、随机、单次提案、仅 DSL LLM、无记忆消融、无策展器消融、无约束 Python 消融），对其每张被接受的候选执行步骤 1–2，再做验证卡片计数。H1 裁定为等同算力预算下的计数对比。
\[ \begin{aligned} \textbf{H1 强结论：} \quad & N^{\,\text{val}}_\text{LBG} \;>\; \max_{B} N^{\,\text{val}}_B \quad\text{且}\quad N^{\,\text{val}}_\text{LBG} \ge \tau \\[4pt] \textbf{H1 弱结论：} \quad & N^{\,\text{val}}_\text{LBG} \ge 1 \quad\text{且}\quad N^{\,\text{val}}_\text{LBG} \ge N^{\,\text{val}}_{B^{*}} \end{aligned} \] \(B^{*}\) 是验证集产量最强的基线，在密封窗口打开 之前 选定，选定结果不得修改。\(\tau\) 是预注册的最小阈值（当前 \(\tau = 3\)），低于此值的正向对比不算有意义的证明。同时报告 \(N^{\,\text{val}}_\text{LBG} - N^{\,\text{val}}_{B^{*}}\) 的自助置信区间。

步骤 4 · 策略层 Δ Sharpe（补充而非 H1）

在组合策略的日收益上做配对差值统计：

\[ \Delta S^{\,\text{strat}} \;=\; \text{Sharpe}(H_\text{final},\, D_\text{sealed}) \;-\; \text{Sharpe}(B^{*},\, D_\text{sealed}) \]

仍然报告（同样以 \(\text{block\_len} = 10\)、\(n = 1000\) 的分块自助置信区间形式）。它回答的是"组合后的策略在这一段密封窗口上是否优于基线策略？"，有用，但不是 H1 裁定。一个产出大量已验证因子、但组合策略不佳的框架仍可通过 H1；反之，一个恰好击败 \(B^{*}\) 的幸运单策略，若其背后没有任何被个体验证的因子，则不能通过 H1。这一重新构造是有意为之：产出的持久性，而非单一产物的头条。

为何用计数而非均值 对 ΔS_c 跨卡片求均值看似诱人但具有误导性。一张贡献极端的卡片可主导均值，掩盖框架其实只靠一个幸运函数的事实。对超过置信阈值的卡片做计数可避免这一陷阱：每张卡片贡献 0 或 1，计数对异常值天然鲁棒。这也与运行实践相符；重新发现时，每张被验证的卡片留存，未被验证的弃用；计数正是因子图书馆所累积的量。

第二层：过程指标的形式化

第二层回答 框架是否真的在学习？ 这一问题，与最终策略是否优秀无关。三个量化检验：

\[ \begin{aligned} \text{acc}_\text{first} &= \frac{\#\,\text{前半段被接受的试验}}{N/2} \\[6pt] \text{acc}_\text{late} &= \frac{\#\,\text{后半段被接受的试验}}{N/2} \\[6pt] \Delta_\text{acc} &= \text{acc}_\text{late} \;-\; \text{acc}_\text{first} \end{aligned} \] \(\Delta_\text{acc}\) 为正与"学习正在发生"一致，但并非充要条件：策略变强后，验证门控本身也会结构性地变得更难通过。该量与其它指标一同报告，不作为硬性门槛。
对每一次试验 \(k\)，编辑器预测 \(\hat{y}_k \in \{\text{accept},\ \text{reject\_drawdown},\ \text{reject\_turnover},\ \text{reject\_complexity},\ \text{reject\_no\_significant\_improvement}\}\)，编排器记录实际结果 \(y_k\)。 \[ \text{校准准确度} \;=\; \frac{1}{N}\sum_{k=1}^{N}\, \mathbf{1}\bigl[\hat{y}_k = y_k\bigr] \] 若编辑器输出关于结果的概率分布 \(p_{k,c}\)，则计算多类 Brier 分数： \[ \text{Brier} \;=\; \frac{1}{N}\sum_{k=1}^{N}\, \sum_c \bigl( p_{k,c} \;-\; \mathbf{1}[y_k = c] \bigr)^{2} \] Brier 分数随试验数下降，是编辑器正在学会预测哪些编辑能通过门控的直接证据。这种过程改进恰好是把 LBG 与随机搜索区分开的关键。
\[ \begin{aligned} \text{复用率} &\;=\; \frac{\#\,\text{首次策展器周期之后引用某技能档的试验}}{\#\,\text{首次策展器周期之后的全部试验}} \\[8pt] \text{技能档命中率}(s) &\;=\; \frac{\#\,\text{使用技能档 } s \text{ 且被接受的试验}}{\#\,\text{使用技能档 } s \text{ 的试验}} \end{aligned} \] 如果复用率随运行进程上升，且至少存在一个技能档 \(s\) 的命中率超过全局接受率，则技能档存储具有存在价值。从未超过基础接受率的技能档将被策展器废弃。

第三层：方法论安全

不变量失败并非同质。编排器对失败进行分类，最终报告予以分类展示：

类别含义重要性
hard_fail无法运行（语法错误、沙箱崩溃）表明智能体产生了结构错误的提案。
safety_fail前瞻、数据窥探、规避成本、违规文件访问奖励黑客尝试的直接证据。最重要。
quality_fail交易过少、换手率过高、复杂度爆炸表明智能体在探索，但未满足门控规范。

如果运行中 safety_fail 计数非零，这就是 H2 的正向证据：不变量套件正是唯一阻止这些尝试污染裁定的机制。报告会逐项列出每一次 safety_fail，包括试验编号、尝试的攻击路径、以及哪一条不变量将其捕获。

第四层：成本诚实，逐项列出

\[ \begin{aligned} \text{tokens}_\text{total} &\;=\; \text{tokens}_\text{editor} + \text{tokens}_\text{reflector} + \text{tokens}_\text{curator} \\[6pt] \text{dollars}_\text{total} &\;=\; \sum_{r \in \{\text{ed, ref, cur}\}}\, \text{price}(\text{model}_r,\, \text{tokens}_r) \\[8pt] \text{每百万 token 接受数} &\;=\; \frac{\#\,\text{被接受的试验}}{\text{tokens}_\text{total}\,/\,10^{6}} \\[6pt] \text{每百万 token 夏普} &\;=\; \frac{\text{Sharpe}(H_\text{final},\, D_\text{sealed})}{\text{tokens}_\text{total}\,/\,10^{6}} \\[6pt] \text{每美元夏普} &\;=\; \frac{\text{Sharpe}(H_\text{final},\, D_\text{sealed})}{\text{dollars}_\text{total}} \end{aligned} \]

这些数字与夏普并列出现在头部对比表中。若审稿人希望在等同算力前提下将 LBG-Trader 与网格搜索或贝叶斯优化作比较，无需重算即可看到这两组数据。

第五层：选择偏倚与预注册

对裁定最隐蔽的威胁不是前瞻，而是多重比较。框架运行多种配置（完整 LBG、仅 DSL、无记忆、无策展器，以及基线集合），若朴素地报告"最优配置达到显著"，结果会系统性夸大效应。

缓解措施：在任何密封测试打开之前，将一份 analysis_plan.yaml 提交到 git，内容包括：

analysis_plan.yaml 
primary_comparison:
  test:           validated_factor_count
  candidate:      full_lbg_trader
  references:     [bo_on_dsl, grid_on_dsl, random_search,
                   one_shot_llm, dsl_only_llm,
                   no_memory_ablation, no_curator_ablation,
                   unconstrained_python_ablation]

  per_card_validation:
    method:       leave_one_out_incremental_sharpe
    ci:           0.95

    h1_strong:    N_val_lbg > max_over_baselines(N_val_B) AND N_val_lbg >= tau
    h1_weak:      N_val_lbg >= 1 AND N_val_lbg >= N_val_B_star
    tau:          3

supplementary_strategy_comparison:
  test:           block_bootstrap_difference
  metric:         sealed_strategy_sharpe
  reference:      best_validation_pre_sealed_baseline
  ci:             0.95
  block_len:      10
  n_bootstrap:    1000
  # 同时报告但不作为 H1 裁定

  - validated_factor_count_per_system
  - per_card_incremental_sharpe_with_ci
  - sealed_strategy_sharpe
  - sealed_strategy_max_drawdown
  - validation_to_sealed_degradation
  - acceptance_rate_trend
  - hypothesis_calibration
  - reuse_rate
  - safety_fail_count
  - tokens_total

multiple_testing_correction:
  family:               per_card_ci_tests
  method:               benjamini_hochberg
  false_discovery_rate: 0.10
  # 此处用 FDR 而非 FWER：每张卡片是独立的发现候选，而非确认性对比。

主比较是按系统计数 N_val，再做对比；H1 强结论要求 LBG 的计数严格大于所有基线，且不低于阈值 \(\tau\)。补充性的策略层 ΔSharpe 仍以 Holm-Bonferroni 控制族系误差率报告。任何未在密封测试打开之前出现在 analysis_plan.yaml 中的比较，将被报告为"事后探索性比较"，且明确不可用于支持 H1。

关于 FDR（错误发现率）与 FWER（族系误差率）的区别：当每个比较是 独立的发现候选（这里是每张卡片是否被验证），用 Benjamini-Hochberg 控制 FDR 在 0.10 是更合适的；FWER 适用于 确认性对比（系统 A 是否严格优于系统 B 一项），后者仍保留给策略层比较。

本节为何最关键 本提案其余部分（不变量套件、脱敏反馈、策展器、双引擎切分）所防范的都是具体的奖励黑客与过拟合机制。analysis_plan.yaml 防范的是 ML 研究论文最常见的失败模式：在看到数据之后才决定测量哪个量。没有预注册，即使一项被完美执行的实验，其裁定也不应被任何诚实的审稿人接受。

五项 HL 性质，各自映射到具体机制

Weng 列出了 HL 应 具备的五项性质。下面给出 LBG-Trader 对每一项的兑现机制，以及本文中该机制的具体出处。意图是让隐含承诺变得可被审计。

1 · 可解释性

HL 论断。 代码策略可翻译为人话；神经网络难以解释。

LBG-Trader 机制。 每个被接受的策略由 (strategy.yaml, indicators/*.py) 配对构成。YAML 是声明式且小巧的；每个指标都是带强制 docstring 的纯 Python 函数；策略解释器固定且可读。最终报告（§17）为每个被接受产物附"一段话讲清策略"的渲染。

验证位置： §4.5（启发式系统形式化）、§6.6（技能档附证据）、§17（最终报告版式）。

2 · 样本效率

HL 论断。 一次有效代码更新即可跳到新策略，无需慢慢爬梯度。

LBG-Trader 机制。 每次被接受的试验都是代码空间中的结构性跳跃。发现预算为每次运行 50 次试验，足够是因为每次编辑可改变特征集合，而不仅仅是参数；这是 BO / 网格基线做不到的。评测第四层（§10.5）显式报告"每百万 token 夏普"与夏普并列，使效率论断在等同算力下可与梯度类基线对比。

验证位置： §5（双时间尺度）、§10.5 第四层（成本诚实）。

3 · 可回归 / 可验证

HL 论断。 旧能力可变成测试、回放或 golden case，在未来变更中存活。

LBG-Trader 机制。 每次被接受的试验都在 artifacts/accepted/trial_NNNN/ 下冻结一个快照。不变量套件在每次候选上重跑，因此任何破坏旧指标前缀稳定性的新编辑都会在被接受之前先失败。失败方向记录在 failed_directions.md 中，用于裁剪后续编辑器提议。策展器每周期对照最新试验集重新验证技能档（§6.6）。

验证位置： §6.5（GitManager + SkillManager）、§9（每候选都跑不变量）、§10 第三层（过程指标）。

4 · 可约束过拟合

HL 论断。 代码启发式也会过拟合，但简化、回归、多 seed 检查能形成一种工程正则化。

LBG-Trader 机制。 我们叠加四道防线：(a) 密封评测（§7），最强一道，运行末尾一次性打开；(b) 多目标门控中的复杂度惩罚（§9），拒绝过大的编辑；(c) 显式可用的 simplify 编辑类型；(d) 在新密封窗口上的重新发现（§13），策略层面的"多 seed"等价物。

验证位置： §7、§9、§10.5 第五层（预注册）、§13（重新发现节奏）。

5 · 避免灾难性遗忘

HL 论断。 旧能力不必由模型自己记住，可以被写进 rule set 和测试里。

LBG-Trader 机制。 git 历史永久保留：每次试验一次提交，每个策展器周期一个分支，不做 rebase。accepted_rules.md 在每次压缩中保留（策展器合并而非无记录删除）。技能档存储携带显式证据指针。任何历史策略产物都可按名称检出并重跑；LLM 无需记住任何东西，框架为它记住。

验证位置： §6.6（四层记忆）、§10（git 纪律）、§13（重新发现间的谱系）。

额外性质 · Weng 博文暗示但未命名

"有一类原来因为维护成本太高而不值得写的启发式，现在突然可能值得长期拥有了。"

LBG-Trader 机制。 技能档（§6.6）的整套概念正是为此而设。技能档不是一次性优化，而是带证据、被框架在每个策展器周期重新验证的可维护配方。因子卡片导出（§6.6）把同一思想推广到信号层，使项目的产出成为一份已评测启发式的图书馆，而非单一策略的点估计。若 H1 成立，这一性质是把框架定位为 研究产品（而非一次性实验）的最终依据。

本映射不承诺什么

两点提醒。第一，满足 HL 性质清单本身并不意味着策略一定泛化；后者由密封测试裁定，H1 / H2 / H3 给出最终结论。HL 性质是必要的基础设施，不是裁定本身。第二，交易引入了 Weng 在 Atari 套件上的实验未触及的失败模式（对抗性回测面、分布漂移、LLM 中潜在的日历先验）。不变量套件（§9）与脱敏反馈纪律（§7）正是为防止 HL 所承诺的性质被这些交易特有的压力悄悄瓦解而存在。如果没有这些防线，上述每条性质技术上仍然成立，但最终策略仍会是错的。

III. 生命周期：从密封评测到部署
§ 11

四个阶段

这一部分是连接科学评测与工程部署的桥梁。每个阶段都有清晰的边界、各自的交付物、各自的通过/不通过决策。阶段之间的迁移由人审议把控，绝不自动晋级。

1 发现

密封评测的 LBG 运行

发现引擎在选定标的与日期范围上运行一次 LBG 循环。输出：两类产物并行：(1) 一组已验证因子卡片（每张是通过密封测试、依 §10.5 第一层得到验证的前缀稳定 Python 因子），(2) 一份组合这些因子的冻结 strategy.yaml + indicators/*.py。再加上一次密封测试裁定与一份最终报告。这是科学核心，针对本次标的、本段时期、本套协议回答 H1/H2/H3。卡片跨多次重新发现留存（§13）；策略每次重新组合。

时长：数小时至一天 · 成本：数十美元的 token · 交付物：已验证因子库 + 组合策略

2 前向验证

在严格晚于密封窗口的数据上的样本外回测

冻结后的策略针对整个发现流程从未触碰的数据运行：严格晚于密封窗口末日的数据。对本里程碑（密封为 2021–2024）而言，第二阶段始于 2025-01-01，使用策略冻结后累积的真实历史。该数据在产物被密封之后才获取，任何发现运行都无法获得。

交付物是一份回测-前向差距报告，以及进入第三阶段与否的决策信号。如果策略的前向表现明显劣于其密封预期，则在此处出局，不再晋级。

时长：数分钟 · 成本：可忽略 · 交付物：通过/不通过决策

3 模拟交易

实时数据、模拟成交

执行引擎在实时市场数据上运行冻结后的策略，使用模拟成交。循环中没有 LLM，只有 policy_interpreter.py 在执行确定性规则。交付物是一个实时仪表盘、一份每日决策日志，以及一个持续更新的回测-模拟差距监控。这是"模拟实践"：系统按实盘方式运行，具备全部操作机制，但不投入真实资金。

时长：数月 · 成本：仅数据源 · 交付物：实盘绩效记录

4 实盘资金

真实资金、券商对接

本提案不覆盖此阶段，但已预留设计空间：执行引擎对接券商，使用少量真实资金交易。风控监控、断路器、对账、审计，均属量化运营的标准实践。该阶段为可选，且以第三阶段表现为通过条件。

时长：持续 · 成本：券商费用 · 交付物：真实收益

四个阶段共同遵守两条原则。

第一，每个阶段的交付物只供下一阶段消费，不跨阶段消费。第一阶段产出冻结产物；第二阶段消费该产物并产出通过/不通过信号；第三阶段（仅在第二阶段通过时）消费该产物并产出实盘绩效记录；第四阶段（仅在第三阶段表现持续时）消费实盘绩效记录。不得跳级。

第二，只有第一阶段调用 LLM。第二、三、四阶段都是纯粹的确定性 Python，仅运行冻结产物。这正是 §5 双时间尺度切分的工程意义：实盘运行无任何 LLM 依赖、无任何按 K 线计费的 token 成本、无任何 LLM 可用性中断风险传导到交易。

各阶段的"典型一天"

上方阶段表是结构性的，下方这张是运行性的：每种"日子"实际发生什么、由谁负责、哪些文件会改动。这是一个运营者会贴在运行手册墙上的内容。

阶段 · 范围"典型一天"
第一阶段
发现

发现"一天"指的是一次完整运行，耗时若干小时，而非 24 小时。具体流程：

  • 运营者提交 analysis_plan.yaml 并以 discovery-NNN-start 标签标注起点启发式系统。

  • 运营者观察实时试验仪表盘，但不与之交互。
  • 预算用完时，编排器恰好打开一次密封测试，写入 artifacts/sealed/discovery-NNN/sealed_test_final.json。

前向验证

一次性的短任务，在每次发现产出冻结产物之后运行一次：

  • 运营者读取该差距，决定进入第三阶段或归档产物。
第三阶段
模拟交易

这是唯一具有真实日度节奏的阶段。一个典型工作日：

  • 09:00：盘前数据刷新；前一日的复权 K 线终结；features.py 重算特征表。
  • 09:05：policy_interpreter.py 消费特征表，输出当日目标仓位。记录到 paper/decisions.jsonl。
  • 09:30：开盘。成交模拟器以开盘价记录模拟成交，应用锁定的 5.5 bp 成本，更新模拟组合。
  • 16:00：收盘。计算日终损益；追加 paper/equity.jsonl；仪表盘刷新。
  • 16:30：回测-模拟差距监控重算。若差距超出阈值 30 天以上，触发重新发现（Slack 告警 + 写入 paper/triggers.jsonl）。

第四阶段
实盘资金

与第三阶段日度节奏相同，叠加券商对接与人工风控审议：

  • 09:05 的决策以订单意图发送至券商抽象层；仅在硬风控检查（仓位上限、回撤断路器）通过后才下发订单。
  • 成交回报由券商返回；与确定性策略对账，任何差异都暂停交易直至审议完成。
  • 日终：除损益外另写一份合规日志（对手方、成交、剩余现金）。资金流与券商对账单核对。
  • 风险经理每周复审异常；确定性内核相对第三阶段保持不变。

这里平淡得令人意外的一点是：第三、四阶段每日的代码路径实际做的事情极少：读取当日 K 线、计算少量指标、输出一个 \([0,1]\) 内的数、记录日志。智能完全在上游，被冻结在 strategy.yaml 与 indicators/ 中。这正是"运行期间拒绝调用 LLM"所兑现的可见收益。

§ 12

两个引擎

从架构上看，四阶段生命周期可被归约为两个引擎。这是本项目最核心的工程切分。

图 4。 两个引擎，共享一个产物。发现引擎运行 LBG 循环以产出冻结策略产物；执行引擎读取冻结产物以执行前向回测、模拟交易或实盘交易。两者从不共享运行时状态。这一切分使科学可信度与运营可靠性得以并存。

这一切分带来若干值得明示的工程后果：

  • 产物可移植。 已发现的策略可在不同机器之间迁移、可在 git 中版本化、可做 A/B 比较、可归档、可恢复。它就是一组文件。
  • 执行无 LLM 依赖。 市场交易时段 Anthropic 服务中断不会停止交易。模拟与实盘只依赖于市场数据源，以及（第四阶段下的）券商连接。
  • 发现无市场数据源依赖。 发现运行作用于历史 parquet 数据，不关心券商是否可用。
  • 故障域隔离。 LBG 循环中的 bug 不会污染实盘组合；执行引擎中的 bug 不会使密封评测失效。

这是把 ML 标准模式（训练管线与推理服务管线分离）应用到 LBG 的结果。

§ 13

周期性重新发现

冻结后的策略终将失效。市场会变；波动结构会切换；新机制开始相关，旧机制逐步衰减。问题不是 要不要 刷新，而是 如何 刷新，同时保留每次刷新的科学可信度。

朴素方式是让智能体从实盘数据中持续学习，这会立刻摧毁密封评测：一旦智能体看到任何数据，该数据从此对它而言不再具有"留出"性质。有纪律的方式是 周期性地在全新密封窗口上重新发现。

图 5。 周期性重新发现通过让密封窗口随时间向前推进，保留密封评测的可信度。每一次重新发现使用一段在上一次发现期间不可见的全新数据。代价是耐心：新的密封预算以真实时间流逝的速率累积。

重新发现的触发条件

触发条件本身就是一项设计选择。健康的选项包括：

  • 日历触发。 每季度、每半年、每年。可预测，易于推理，预算稳定。
  • 表现触发。 回测与实盘的差距超过阈值（例如实盘夏普低于密封预期 0.3 以上且持续 30 天以上）。由第三阶段监控触发。
  • 风险触发。 实盘回撤超过阈值，策略下线，直至重新发现完成。
  • 数据可用性触发。 当新数据已累积到足以支撑一个有意义的新密封窗口时触发。

实际中，触发器会叠加：制度切换通常会让表现触发器先于日历触发器报警。健康的默认是"日历触发 + 表现提前触发"。

两次重新发现之间：策略保持冻结

两次重新发现之间，策略保持冻结。执行引擎只是在当前激活的 strategy.yaml 与 indicators/ 上运行 policy_interpreter.py。无编辑、无 LLM。这正是日常运行得以廉价、可靠、可复现的原因。

这也意味着对每一个标的池而言，始终恰好存在一个激活的策略产物，且谱系清晰。若 Q1 策略为 2026-Q1_spy_a，Q4 重新发现产出 2026-Q4_spy_a，则后者干净地替代前者，前者归档以便历史对比与审计。

因子库则相反，它 累积。Q1 的已验证因子卡片不会被 Q4 重新发现作废，它们仍是因子卡片库的条目，如果在 Q4 的密封测试上仍然能验证，可被重新组合进 Q4 策略。Q4 发现运行以并集（Q1 卡片 + 新候选）为种子池启动：一些 Q1 卡片在新密封窗口上不再通过验证（被标 deprecated 并附带日期注释）；一些继续通过验证、被复用；一些新候选被加入。多次重新发现后，策略产物在更替，因子库的规模在上涨、坏率在下降。这种复利正是 §2 中"持久性"论断的运行化兑现。

§ 14

标的池过滤器，而非标的选择

一个诱人的特性是让智能体 选择交易哪个标的。须抵抗这一诱惑。让智能体从大池中挑选标的，会引入灾难性的多重比较选择偏倚：如果智能体悄悄在五十只候选标的上运行发现并只报告最佳者，所报告的密封夏普几乎肯定来自运气，而非技能。

有纪律的替代方案是：智能体学习一个面向标的池可应用的策略，并由确定性过滤器决定交易哪些标的。发现运行锚定在单一标的（或一个小标的池）上，智能体的策略只能通过声明式准则、而非直接命名标的来表达其可交易范围：

strategy.yaml 中的 universe_filter 
universe_filter:
  min_market_cap_usd: 10_000_000_000
  min_avg_daily_volume: 1_000_000
  min_price: 10
  exclude_sectors: [financials]
  exclude_etf_categories: [leveraged, inverse]

部署阶段，该过滤器作用于更广的市场，产出策略可运行的标的清单。智能体并未挑选这些标的，而是声明了它的策略所适用的条件。

这一约束与专业量化研究中因子的设计原则一致：因子是一个面向标的池可应用的函数，而非针对特定标的的预言。我们沿用这种纪律。

关于多标的 本提案描述的最小可行版本（MVP）在单一标的（SPY）上训练。真正的多标的跨截面学习属于较大的范围扩展，被视为未来方向，而非当前里程碑。上文 universe_filter 的抽象为日后扩展到多标的留出空间，使得扩展是增量式的，而非破坏性的。
§ 15

在线 HL：一个不同的研究问题

提案评审中提出过一个自然的问题：为什么不让智能体在线、实时地从实盘交易结果中持续学习？ 策略永不冻结、永远演化。这在概念上颇具吸引力：它会把 LBG-Trader 变成一个完全的持续学习者，更接近在线强化学习。

诚实的回答是：这是一个不同的研究问题，而非本项目的延伸。原因有以下几条。

在线 HL 的难点

它直接瓦解密封评测。 一旦智能体看到实盘数据，该数据再不可作为留出。"是否泛化？"这一概念将丧失意义。可用的最强评测降级为滚动前向表现，其噪声大、推断功效弱。

智能体会追逐噪声。 每次更新都基于近期样本；近期样本噪声大。若无密封测试做真值锚定，智能体将系统性、长期地做出局部看上去有效、实际并非真实信号的修改。

缺乏干净的停止准则。 Token 成本无限累积，记忆无限增长，系统永不"完成"。

这是文献中的开放问题。 Weng 自己的实验都是批量学习（把任务跑到收敛）而非在线。在线 HL 处于研究前沿，方法论尚未定型。

带周期性重新发现的四阶段生命周期，几乎实现了在线 HL 所承诺的一切（策略随市场演化），同时保留了在线 HL 所放弃的大部分（每次刷新都有可信的密封评测）。这正是量化行业实际采用的"有纪律的中间路径"。

我们将在线 HL 明确记录为未来方向。若本提案第一至三阶段获得成功，且周期性重新发现的节奏在某些市场上被证明过慢，后续项目可以探索在线 HL 并重新设计评测框架，以更弱的统计推断换取更紧的循环。那是一份不同的文档。

§ 16

人的位置：按阶段

框架在不同阶段赋予人不同的角色。贯穿所有阶段的一条原则是：人不做逐笔交易决定，亦不在 LLM 循环中途介入。人只在阶段交界处作用，不在阶段内部作用。

第一阶段之前
方法学家

设计协议：选定标的、划分、DSL schema、编辑类型、不变量、门控阈值、基线、模型选择、停止准则。这些一旦冻结，便对整次运行锁定。这是整个项目中最具决定意义的人为贡献。

第一阶段进行中
有纪律的非参与者

观察试验监视器，不作干预。可在出现严重 bug 时中止；不得根据所见调整提示、阈值或记忆。运行进行中人唯一被允许做的事，是彻底停止运行，绝不允许修改运行。这种纪律正是密封裁定可信度的来源。

第一阶段之后
科学家

阅读最终报告，给出 H1/H2/H3 裁定，撰写发现。决定是否进入第二阶段（前向验证），或修订协议、在不同标的、不同划分或不同配置上发起新一轮发现。

第二到第三阶段过渡
审议者

阅读前向验证差距报告，决定是否进入模拟交易。在此阶段失败的策略被归档，而非被打补丁；对一个已通过密封测试的策略在其前向数据上打补丁，会把信息倒灌回策略，构成泄漏。

第三阶段进行中
运营者与组合管理者

监控实时的模拟交易仪表盘，关注回测-模拟差距，决定何时停止退化中的策略（性能恶化）、何时触发提前重新发现（制度切换）、何时在多个活跃策略之间调整资本分配。不干预个别交易。

第三到第四阶段过渡
风险经理

不在本提案覆盖范围内，但出于完整性予以记录：制定硬性风险上限，配置断路器，处理券商对接与对账，管理合规要求，掌控紧急停止按钮。该角色的标准由外部约束决定（券商、司法辖区、资金来源），与本提案无关。

各阶段的共同模式是：人作用于阶段交界与基础设施，系统作用于阶段内部。在实际工程中，这一模式容易被破坏的方式（人偷偷在运行过程中调整东西）已被协议显式防御：任何此类调整将使裁定失效。

§ 18

工程计划

本计划详述第一阶段（发现），以及与后续阶段共享的基础设施。第二、三阶段的部署工作在 §11 中描述，仅以高层节奏给出时间安排；它们位于第一阶段裁定的下游。

第 1 周 · 共享基础设施

数据、回测引擎、划分、经典基线

通过 yfinance 获取 SPY 2010–2024 数据，与 Stooq 交叉核验，存为版本化 parquet。编写 features.py，固定特征集合。实现约 150 行的向量化回测，包含成本模型与前瞻不变量。实现 policy_interpreter.py（被两个引擎共用）。实现买入持有、SMA 双均线、随机搜索、网格搜索、贝叶斯优化等基线。退出条件：买入持有指标与独立实现的参考值在容差范围内一致（指示性区间：年化夏普视成本假设处于 0.7–0.9）；扣除成本后的随机搜索中位夏普接近零；§10.5 中的第零层健全性检查全部通过。

第 2 周 · 仅编辑 DSL 的 LLM 循环（消融基线）

带脱敏验证的编辑器/反思器循环

实现 DSL schema，编写编辑器与反思器提示，实现结构化提案解析、机械化的假设结果判定、仅追加的 trials.jsonl。以仅 DSL 的编辑运行 N=50 次试验。这是消融基线。退出条件：完整试验日志生成，密封测试推迟。

第 3 周 · 程序合成层

指标编写、AST 不变量、沙箱

新增 add_indicator 编辑类型，实现基于 AST 的静态不变量套件（无未来 shift、无负索引、白名单 import、纯函数），实现带超时与内存上限的沙箱执行，实现动态前瞻测试。正是这一层把项目从 LLM-BO 升格为 LBG。退出条件：一个违反前瞻不变量的指标函数被正确捕获。

第 4 周 · 策展器与完整发现运行

§ 19

风险

按"该风险对结论意味着什么"排序，而非按发生概率排序。

回测过拟合

核心科学风险。如果智能体通过了验证却在密封测试上失败，本项目所证明的只是密封协议下过拟合机制的强度。缓解措施：DSL 约束、多目标门控、脱敏验证、密封写一次、分块自助置信区间。最后一道防线是诚实地把失败报告为 H1 负面结局。

奖励黑客

核心工程风险。被赋予 Python 执行能力的编码型智能体，会发现前瞻、利用成本模型的边界条件、操纵索引对齐，或在异常处理中隐藏失败交易。缓解措施：不变量套件、AST 静态分析、沙箱执行、动态前瞻测试。无约束 Python 的消融实验专门用以测量当不变量关闭时这种情况会恶化到什么程度。

部署阶段的分布漂移

通过第一阶段密封测试的策略，可能在第二或第三阶段前向运行时失败，因为市场已经变了。这不是 LBG 的失败，而是市场的属性。缓解措施：把第二阶段前向验证作为硬门控；第三阶段持续监控回测-模拟差距；表现触发的重新发现。

LBG 论断的过度声张

最强烈的诱惑是将"H1 正面"解读为"LBG 有效"。可被辩护的论断要窄得多："LBG 在本 DSL、本标的池、本时期、本协议下有效"。缓解措施：把仅 DSL 的消融放进头部对比表；把 token 成本与夏普并列报告；在密封测试打开之前承诺每种结局的含义。

启发式系统的膨胀

若无策展器，accepted_rules 与 indicators 会累积为一团泥球。缓解措施：每次试验报告复杂度指标；从第一天起启用影子策展器；主动策展器须以验证复查为通过条件。

对底层 LLM 的依赖

框架在外层循环上部分地依赖一个神经网络，其表现取决于所用模型。在更弱或不同的模型上无法复现，是发现而非致命缺陷，但必须显式记录。缓解措施：报告模型版本与 token 成本；考虑在更弱模型上做一次消融运行。

部署风险（第三至四阶段）

即使第二阶段通过，回测-实盘差距仍可能超出可接受范围。券商对接引入了本提案未覆盖的运营复杂度。缓解措施：实盘前必须模拟交易；基于性能的断路器；部署阶段风险面在另一份运营设计中专门记录。

§ 20

锁定清单

下列决策对本里程碑冻结。在运行过程中修改其中任何一条，都会使密封测试失效，并需要重置里程碑。

已冻结的决策

  1. 仓库命名为 lbg-trader；论文标题为 Sealed-HS: Persistent Heuristic Learning under Sealed Evaluation
  2. 第一阶段发现使用单一标的 SPY，日频，2010-01-04 至 2024-12-31
  3. 三划分：训练 2010–2018，验证 2019–2020，密封 2021–2024；在智能体上下文中以 split_A/B/C 别名出现
  4. 智能体动作空间：Python 纯函数指标编写 + DSL 编辑；八种离散编辑类型
  5. 四类 LLM 角色：编辑器 / 反思器 / 策展器 / 翻译器；本里程碑中策展器为影子模式，翻译器仅在 add_indicator 被接受后做声明式 dossier 输出
  6. 对 LLM 的验证反馈仅为类别，绝不为数值或曲线
  7. 假设结果由编排器机械化判定，不由反思器判定
  8. 所有回测之前先运行不变量：schema、AST 静态、前缀稳定性动态、成本模型、沙箱、无数据窥探
  9. 单次试验 验证门控使用 \(\alpha = 0.20\) 的多目标效用下界加帕累托改进；不 要求每次试验都满足 CI > 0
  10. 最终 H1 裁定 使用 配对差值 的移动块自助检验（块长 10，重抽 1000），对照预注册的最强基线；95% 置信区间下界 > 0 为强结论标准
  11. 单边有效成本锁定为 5.5 bp（基础 5.0 + 滑点代理 0.5）；对所有系统（含基线）统一应用
  12. 持久化通过 git：每次试验一次提交，每次策展器周期一个分支
  13. 智能体计算量按角色与按 token 效率报告，进入基线对比表
  14. 密封测试恰好打开一次；sealed_test_final.json 仅写一次
  15. 阶段 0.5 基线（随机、网格、BO）在任何 LLM 驱动运行之前完成
  16. 仅 DSL 的 LLM 循环是消融，而非阶段；与完整系统并行运行
  17. 策略在两次重新发现之间保持冻结；第二/三/四阶段绝不编辑
  18. 重新发现使用全新密封窗口；旧密封窗口绝不复用
  19. 对 SPY 里程碑，框架将标的池 固定 为 SPY；智能体不选择标的。§14 中的 universe_filter 机制仅作用于未来的多资产里程碑
  20. 第二阶段前向验证使用严格晚于 2024-12-31 的数据；该数据在第一阶段密封之后获取，发现运行绝不可获得
  21. 在线 HL 不在本里程碑范围；作为未来方向记录于 §15
  22. analysis_plan.yaml 必须在任何密封测试打开之前提交至 git；主比较与次级比较在此处预注册
  23. 次级比较使用 Holm-Bonferroni 法控制族系误差率于 0.05
  24. 技能档产物遵循 §6.6 schema；策展器输出为带类型对象，非自由形式文本
  25. 指标函数须满足前缀稳定性（§4.5）；动态不变量通过扰动测试强制执行
  26. 每一次新增或修改指标且被接受的试验，须导出因子卡片（§6.6）
  27. 日历标签（年份、命名事件）仅出现在面向人的最终报告与编排器内部日志中，绝不出现在智能体提示模板或任何 ContextBuilder 可读的文件中
  28. HL 的学习对象是启发式系统：indicators/*.py（Python 因子函数）、strategy.yaml、若干显式记忆层、git 谱系四者的并集。在此系统内 LBG 真正产出的核心产物，是智能体编写的 Python 因子函数集合。Dossier 与因子卡片是这些函数的翻译/元数据视图，并非交付物本身
  29. H1 的统计单位是 幸存的 Python 因子函数，通过其因子卡片做计数操作：一个函数其个体 pathwise 增量密封夏普（按发现循环中卡片被接受的时间顺序，逐次比较"已接受卡片 \(\le c-1\)"与"已接受卡片 \(\le c\)"的策略在密封窗口上的日收益）的 95% 分块自助置信区间下界 > 0（block_len 10、n_bootstrap 1000）。H1 裁定为等同算力预算下各系统的计数对比；H1 强结论要求 LBG-Trader 的计数严格大于最强基线，且不低于 \(\tau = 3\)。单卡片验证的多重检验校正用 Benjamini-Hochberg 控制 FDR 于 0.10。完整 LOO 版本作为稳健性附录报告，但 H1 的预注册裁定以 pathwise 版本为准
  30. 因子卡片 schema（§6.6）锁定为 knowledge/factors/dossiers/ 中输入 dossier schema 的 超集：声明式字段（factor_name、core_analysis、parameterization、combination_and_fusion）加可执行证据（python_implementation_path、prefix_stability_passed、sealed_evidence、status）。这使 Python ↔ dossier 双向翻译有明确定义
  31. 已验证因子库为追加式，跨多次重新发现共享。第 N 次运行的幸存函数（及其卡片）进入第 N+1 次运行的种子池；在新密封窗口上重新验证后，要么保留、要么标 deprecated、要么合并。函数绝不无记录丢弃
  32. 外部因子档案存放于 knowledge/factors/（只读、跨多次运行共享），仅通过 lbg.knowledge.search() 暴露给编辑器。任何档案引用都不豁免任何不变量或密封测试
